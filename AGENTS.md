# ChatSOP agent guidance

## Scope

This is the single root instruction file for changes to ChatSOP. The product's checked SOP language, with one small-model language (DS021) and no versions or profiles, turns natural-language proposals or explicit `.sop` programs into results grounded in reviewed knowledge. Follow the current user request, this guidance, and the design specifications; track outstanding work in `TODO.md` and delivered work in `PAS_TASK.md` without presenting either as product documentation. Open questions that need the owner's decision go in the root `questions.md` (always present; each question has a stable ID, context, options, a recommendation and an empty answer line); once a decision is implemented, remove the question from that file and record the decision in the owning DS, `PAS_TASK.md` or `CHANGES.md`.

## Model boundary (non-negotiable)

The small formalizer has no context: its prompt is exactly the user's message, with no CONTEXT block, entity or predicate list, identifiers, lexicon, background knowledge or clock. It writes one language (DS021; no versions or profiles, no `premise`), one keyword per line: `stated` (only what surely comes from the message; `certainty asserted|hedged|supposed`, optional `speaker` for reported speech), `assumed` (anything the model adds, including a chosen reading of a vague or ambiguous message; optional descriptive `basis`), `unclear` (`gibberish`, `no_request`, or `ambiguous` with 2–4 `reading` lines, alone), `query` (`where match … end` blocks in `all`/`any`/`end` groups, `mode every` + `scope`, `role time ?t` + `measure`, `mode count`, `mode explain`) and `constraint`. Values are quoted strings as written in the message (`relation "works at"`, roles from `subject`/`object`/`recipient`/`location`/`source`/`destination`/`instrument`/`time`/`topic`) or `?variables`. The model never reasons and never refuses. Linking strings to knowledge is host work after the model; a formalized problem without an engine is answered `not_computable`, and `unsupported` is reserved for rule 8. `setup_sop`, `ontology_sop`, `expected`, `context` and any per-row lexicon are verification scaffolding, never model input. Guards: `tests/model-input-boundary.test.mjs`, `tests/no-context-lint.test.mjs` (`tools/lint/model-surface.mjs`), the corpus-audit check `vocabulary.model_target_id_token`, `tools/verify-vocabulary.mjs`, and `tests/wire-help.test.mjs`, which executes every example of the wire help pages; every wire change updates `docs/wire_types.html` and `docs/wire_typs/` with examples.

## Direction

1. Sequence work from this repository refactor through sourced datasets, ingestion skills and evaluation, then qualified training, API work and controlled comparisons, then an evidence-backed article. `TODO.md` tracks the actual gates; product documentation never asserts progress.
2. Coordinate all training and GPU inference/evaluation under a single GPU-intensive worker per machine. Do not add concurrent GPU jobs, kill unrelated work, or clean unknown checkpoints. A preflight and an import alone do not establish a valid training run.
3. The current user explicitly prohibits training until **new explicit approval**. Image build, dependency setup, CUDA infrastructure preflight, safe stop and dataset qualification are allowed; no `train`, `--resume`, fine-tuning, optimizer step or training smoke run is authorized. Approval is never inferred from a passing preflight or qualification report.
4. Keep two learning flows distinct: the small formalizer maps questions and supplied assertions to SOP; material ingestion extracts quoted source claims and requires independent host approval before knowledge accumulates. New knowledge need not retrain a model.
5. Keep the small model's authored language to `stated`, `assumed`, `unclear`, `query` and `constraint` as described in "Model boundary" above; do not teach the model to emit plumbing operations. The host generates inspectable execution circuits for linking, resolution, collection, solving, rendering and clarification. Asserted statements are turn-local evidence retained only in caller-owned conversation context; suppositions, reported speech and model assumptions are used only conditionally or reported; none is a sourced fact or an implicit repository write. `remember` is a trusted runtime operation, not a TDD assertion or model instruction. The default answer language is English; Romanian on request (API `language` or an explicit request in the message).
6. SOP relations use whitespace-separated terms and JSON-quoted text, not parentheses or commas. Boolean conditions use explicit `all`/`any`/`end` groups. Preserve genuine JavaScript, solver syntax, and exact source quotations separately from SOP grammar.
7. A read must not hide a write. Proof-use promotion of an admitted, metadata-verified observed fact is allowed only when host policy (`policy.reinforce !== false`) and the memory retention configuration (`reinforceOnUse`) both permit it, only for a real non-hypothetical proof, and the reason packet must report it. Candidate retrieval alone never promotes anything.
8. A requested backend is never substituted. An explicit unavailable solver returns `unsupported` with the requested backend named in `route.backend` and `fallback: null`; a JS-only mode with an explicit external backend and the reference strategy with an external backend are rejected the same way; incompatible request/backend profiles fail with a clear error. `advanced` is routing, not a fourth solver.
9. Test and data authority: the authoritative sealed test exports live under `eval/suites/**` (no `test.jsonl` is kept under `datasets/`), and training/selection code reads only the `datasets/<corpus>/{train,dev}.jsonl` splits. `eval/reports/current/` holds regenerable observations and `eval/reports/history/` holds archived numbers; never present a historical number as a current run.
10. Source rights are per asset, not per software licence: only source text recorded as cleared or permissive-attribution in `DS014-source-rights.md` may be ingested, exported or published, and unverified/restricted source text stays in the local source cache `datasets_sources/` and is never exported. By the owner's decision of 2026-09-28, corpora inspired by QQP, PAWS, ProofWriter, AmbigNQ, QA2D and SQuAD are released (`inspired-by-released`): they take structure, label types, phenomena and statistics, never text, and must pass `node tools/datasets/no-copy.mjs` (no 4-gram shared with a row's own source row, no 8-gram shared with any source, no ids in natural language). `datasets/SOURCES.md` lists each source, URL, licence and what was and was not taken; `tools/datasets/rights.mjs` supplies the provenance fields.
11. The corpora are JSONL-first. `datasets/<corpus>/{train,dev}.jsonl` and the sealed `eval/suites/<corpus>/test.jsonl` are the dataset artifacts; there is no Markdown layer under `datasets/` (the Markdown authoring path was retired on 2026-09-28). A human reviews the data through the visual corpus audit (DS020), which is mounted at `/audit` on the main server (`npm start`, default `0.0.0.0:9999`, all interfaces) and requires the administrator session from `/admin`; it re-executes cases on demand and appends verdicts to `eval/reports/current/audit/<corpus>.jsonl`. `node tools/datasets/audit-corpus.mjs --corpus <name>` is the machine audit: it writes `eval/reports/current/corpus-audit/<corpus>.json`, always fails closed on any structural invariant violation, and adds semantic-faithfulness, context-triviality, diversity and template-leakage checks whose failing set `--fail-on` selects (default: every error-severity check); `node check-datasets.mjs` runs it in report mode. Its procedure is `skills/corpus-audit/SKILL.md`.

The normative contracts behind these rules live in the DS set; where this file and a DS disagree, the DS is the source of truth for documented behavior.

Write persistent documentation, specifications, instructions, and code comments in clear English. Keep intentional linguistic data and exact quoted source material in their original language.

## Project journal

Every agent that starts, finishes or blocks a meaningful task, or records an owner decision, appends one event to `status/journal.jsonl` with `node tools/journal.mjs add --area <data|language|eval|training|server|docs|process> --state <started|progress|done|blocked|decision> --title "…" --detail "…" [--link <path>]…` (actor from `CHATSOP_ACTOR`). The journal is append-only: never edit or delete a line; correct a mistake with a new event. Experiment records (id, hypothesis, DS010 preregistration link, data version, status, results, conclusions) go to `status/experiments.json`. The server's `/project` page ("Fine-tuning & status") is the owner's real-time view of both; `/eval` shows the evaluation data behind any result.

1. `README.md`, then `docs/index.html`, `docs/runtime.html`, `docs/training.html`, and canonical terminology at `docs/wiki.html`.

Design specifications are the source of truth for documented behavior and structure; keep them declarative, gap-free in numbering (`node tools/check-spec-refs.mjs`), and synchronized with the HTML pages. Former ids are mapped in `docs/specs/aliases.json` and survive only in archives, the journal and historical reports.
3. Task skills: `skills/training-rules/SKILL.md`, `skills/training-runbook/SKILL.md`, `skills/night-orchestration/SKILL.md` for training; otherwise the owning `skills/<name>/SKILL.md`. The two matching `.agents/skills/training-*` entries point to the corresponding local skill folders; other `.agents/skills/` entries point to an external task-skill catalog and do not supersede this root file or the DS contracts. Product workflows under `skills/` are task procedures, not independent runtimes; `material-to-sop` keeps drafts and candidate rules unapproved until scoped probes and host authorization. The catalog is listed in `skills/README.md`; update it when implemented product skills change.

Archived material (legacy requirement chapters, consolidation registers, the vision and manuscript audits, past proposals) lives under `probably_obsolete/`, indexed by `probably_obsolete/specs/README.md`; it is historical evidence, never required reading.

## Runtime Defaults

Node.js >=22.13 with `.mjs` modules, explicit imports, `node:` built-ins, async/await, and module-relative resources. Prefer built-ins and small auditable local code; record any necessary dependency in root `dependencies.md` or the owning skill's record. Keep Python only for indispensable model training and inference under `training/python/`; never install solvers, models, or packages, and never run GPU work merely to start the symbolic runtime. `docs/specs/DS001-coding-style.md` holds the full effective contract.

## Key Paths

`docs/index.html` is the HTML entry, `docs/runtime.html` explains execution, `docs/training.html` covers model/data boundaries, `docs/wiki.html` defines terminology, `docs/specs/` holds the authoritative DS set, and `docs/specsLoader.html?spec=matrix.md` opens its matrix. `lib/`, `sop/`, `memory/`, `reasoning/`, and `server/` separate runtime concerns; `config/` contains runtime configurations and the host ontology; `status/` holds the project journal and experiment registry; `tools/` owns conversion, validation and review tooling (`tools/datasets/` for data pipelines); `datasets/` holds data artifacts only, with the raw source cache at `datasets_sources/`; `models/<model>/<run>/`, `eval/`, `examples/`, and `tests/` own their respective artifacts (demo/fixture SOP lives under `tests/fixtures/`). `probably_obsolete/` preserves archived evidence; `eval/reports/history/` preserves historical observations and `eval/reports/current/` fresh ones. Verify changed paths through executable behavior before reporting results.

No repository file (tracked, or untracked and not gitignored) may exceed 50 MB: large JSONL is stored as `<name>.part-NNN.jsonl` shards written and read through `lib/jsonl-shards.mjs` (Python: `training/python/common.py`), `node tools/shard-large-files.mjs` shards oversized files in place, and `node tools/shard-large-files.mjs --check` and `tests/file-size-limit.test.mjs` enforce the limit.
