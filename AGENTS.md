# ChatSOP agent guidance

## Scope

This is the single root instruction file for changes to ChatSOP. The product's checked SOP language, with one small-model language (DS021) and no versions or profiles, turns natural-language proposals or explicit `.sop` programs into results grounded in reviewed knowledge. Follow the current user request, this guidance, and the design specifications; track outstanding work in `TODO.md` and delivered work in `PAS_TASK.md` without presenting either as product documentation. Open questions that need the owner's decision go in the root `questions.md` (always present; each question has a stable ID, context, options, a recommendation and an empty answer line); once a decision is implemented, remove the question from that file and record the decision in the owning DS, `PAS_TASK.md` or `CHANGES.md`.

## Names and datasets (owner decisions of 2026-09-30)

Use these names everywhere (glossary: `docs/wiki.html`, DS021 "Names, roles and datasets"): **SymbolicLM** (Stanza grammatical analysis plus the UD-to-SOP rules; returns the grammatical `analysis` and, at a later stage, SOP Lang; the current formalizer, evaluated on clean English); **LanguagesUtil** (language identification and symbolic spelling); **TranslatorService** (translation backends); **textToCleanEnglish** (the chat UI step, validated by the user, that turns bad input into acceptable English; it calls LanguageProofingLLM and LanguageTool); **LanguageProofingLLM** (a standard or fine-tuned LLM for Romanian, mixed and badly written English into acceptable English; Gemma 3 270M first, larger only if it fails; currently the fine-tuned Gemma 3 270M, production build, run `language-proofing-gemma270m-prod1`); **SymbolicProofingLLM** (the small fine-tuned LLM that rewrites correct English into the limited English SymbolicLM understands; currently the fine-tuned Gemma 3 270M formerly called the "proofreader" — keep the frozen role id `proofreader` and artifact paths such as `models/gemma/proofreader-gemma270m-v1`, but name the concept SymbolicProofingLLM). The small formalizer LLM of the model boundary below is earlier work, with results in the archive and history reports. The first level of `datasets/` holds exactly the three datasets `bad_english` (Romanian, mixed and badly written English; LanguageProofingLLM material), `symbolic_english` (correct English SymbolicLM analyses correctly; stores the analysis; the regression suite `tools/symbolic-regression.mjs`), decided on the ANALYSIS layer (every sentence: identical default and accurate Stanza trees and the DeepSeek parse judge, conditions a and c, good enough; the SOP result stays on the row as `sop_layer` for the later layer and never decides the membership; DS008 "Three datasets") and `neuro_english` (correct English SymbolicLM does not analyse correctly; SymbolicProofingLLM material); and, since the owner decision of 2026-10-01, `natural` (the owner's own chat messages: the realism evaluation set, read as a whole, and seeds for synthetic training rows that keep a message's form and change its words; `tools/datasets/audit/natural-overlap.mjs` fails closed on a repeated message or its content words; no splits, no targets; DS008 "The natural collection"); legacy corpora live in `datasets_archive/` (resolver `lib/dataset-paths.mjs`). Priority: improve SymbolicLM by rules and repairs, rewrite only what rules cannot fix. Base models must run at 30 to 40 tokens per second on an ordinary laptop CPU (`eval/reports/current/cpu-speed/cpu-speed-table.json`).

## Model boundary (non-negotiable)

The small formalizer has no context: its prompt is exactly the user's message, with no CONTEXT block, entity or predicate list, identifiers, lexicon, background knowledge or clock. It writes one current language (DS021; no versions, profiles or side-by-side formats, no `premise`; each improvement replaces the old form and the corpora are converted or regenerated), one keyword per line: `stated` (only what surely comes from the message; `certainty asserted|hedged|supposed`, optional `speaker` for reported speech), `assumed` (anything the model adds, including a chosen reading of a vague or ambiguous message; optional descriptive `basis`), `unclear` (`gibberish`, `no_request`, or `ambiguous` with 2–4 `reading` lines, alone), `query` (`where match … end` blocks in `all`/`any`/`end` groups, `mode every` + `scope`, `role time ?t` + `measure`, `mode count`, `mode explain`), `constraint` and `unparsed` (a verbatim `span` of the message it could not formalize, optional `near $id` and `hint`; the role it would fill holds a placeholder `?variable`). One finite clause is one wire: a clause is never stuffed into a string; subordination is a link keyword line (`because`, `so`, `if`, `unless`, `although`, `so_that`, `before`, `after`, `when`, `while`, each with `$id`, `sop/enums.mjs` `LINK_KEYWORDS`), a role value may be `$id` (a clause as an argument, or `$q`, the answers of an earlier query), at most one per wire. Values are quoted strings or `?variables`; roles come from `subject`/`object`/`recipient`/`location`/`source`/`destination`/`instrument`/`time`/`topic`. The model does not translate (owner decision D1): content words stay in the message's language, normalized (relation lemmas such as `"lucra la"`, common nouns in the nominative), a mixed message keeps each word in its language, proper names stay as written and the structural keywords are English; English content words are accepted too. The host normalizes and translates content strings with the reviewed dictionary (`sop/dictionary.mjs`, `config/dictionary/`), reports an unknown word as `untranslated` and never guesses; the knowledge and the reasoner stay English-only. The model never reasons and never refuses. Genuinely ambiguous phrasings are formalized with all plausible readings, never dropped or refused. Repairing unparsed spans and linking strings to knowledge are host work after the model; a formalized problem without an engine is answered `not_computable`, a link without an engine is reported `not_checked`, and `unsupported` is reserved for rule 8. `setup_sop`, `ontology_sop`, `expected`, `context` and any per-row lexicon are verification scaffolding, never model input. Guards: `tests/model-input-boundary.test.mjs`, `tests/no-context-lint.test.mjs` (`tools/lint/model-surface.mjs`), the corpus-audit check `vocabulary.model_target_id_token`, `tools/verify-vocabulary.mjs`, and `tests/wire-help.test.mjs`, which executes every example of the wire help pages; every wire change updates `docs/wire_types.html` and `docs/wire_typs/` with examples.

## Direction

1. Sequence work from this repository refactor through sourced datasets, ingestion skills and evaluation, then qualified training, API work and controlled comparisons, then an evidence-backed article. `TODO.md` tracks the actual gates; product documentation never asserts progress.
2. Coordinate all training and GPU inference/evaluation under a single GPU-intensive worker per machine. Do not add concurrent GPU jobs, kill unrelated work, or clean unknown checkpoints. A preflight and an import alone do not establish a valid training run.
3. The current user explicitly prohibits training until **new explicit approval**: the earlier scoped approval is spent, and no fine-tuning of LanguageProofingLLM or SymbolicProofingLLM (Gemma 3 270M is the base to try first for both) starts until the three datasets are completely cleaned, present on disk, well presented in the audit page and the owner gives an explicit OK. Image build, dependency setup, CUDA infrastructure preflight, safe stop and dataset qualification are allowed; no `train`, `--resume`, fine-tuning, optimizer step or training smoke run is authorized. Approval is never inferred from a passing preflight or qualification report.
4. Keep two learning flows distinct: the small formalizer maps questions and supplied assertions to SOP; material ingestion extracts quoted source claims and requires independent host approval before knowledge accumulates. New knowledge need not retrain a model.
5. Keep the small model's authored language to `stated`, `assumed`, `unclear`, `query`, `constraint` and `unparsed` as described in "Model boundary" above; do not teach the model to emit plumbing operations. The host generates inspectable execution circuits for linking, resolution, collection, solving, rendering and clarification. Asserted statements are turn-local evidence retained only in caller-owned conversation context; suppositions, reported speech and model assumptions are used only conditionally or reported; none is a sourced fact or an implicit repository write. `remember` is a trusted runtime operation, not a TDD assertion or model instruction. The default answer language is English; Romanian on request (API `language` or an explicit request in the message).
6. SOP relations use whitespace-separated terms and JSON-quoted text, not parentheses or commas. Boolean conditions use explicit `all`/`any`/`end` groups. Preserve genuine JavaScript, solver syntax, and exact source quotations separately from SOP grammar.
7. A read must not hide a write. Proof-use promotion of an admitted, metadata-verified observed fact is allowed only when host policy (`policy.reinforce !== false`) and the memory retention configuration (`reinforceOnUse`) both permit it, only for a real non-hypothetical proof, and the reason packet must report it. Candidate retrieval alone never promotes anything.
8. A requested backend is never substituted. An explicit unavailable solver returns `unsupported` with the requested backend named in `route.backend` and `fallback: null`; a JS-only mode with an explicit external backend and the reference strategy with an external backend are rejected the same way; incompatible request/backend profiles fail with a clear error. `advanced` is routing, not a fourth solver.
9. Test and data authority: the authoritative sealed test exports live under `eval/suites/**` (no `test.jsonl` is kept under `datasets/` or `datasets_archive/`), and training/selection code reads only the `datasets/<name>/{train,dev}.jsonl` splits (the legacy corpora's `datasets_archive/<corpus>/{train,dev}.jsonl`); the mechanical guard `eval/leakage.mjs` (`tests/eval-registry.test.mjs`, `tests/audit-corpus.test.mjs`) stays: generators and training code never read `eval/suites/**` test files. Evaluation policy (owner decision of 2026-09-30, DS008 "Form coverage and form variants", DS016 "Composed metrics"): evaluation is an engineering check, and the only generalization tested is the same sentence form with different words. A test is a lexically disjoint variant of forms the system was built or trained on: every form of a test split has train cases of the same form with different content words (`tools/datasets/form-variants.mjs`, `tools/eval/test-variants.mjs`), and the content-word check (`tools/datasets/audit/content-word-overlap.mjs`, run by `tools/datasets/verify-three-datasets.mjs`) fails closed on an exact or normalized duplicate and on a lexical duplicate (identical content words and identical form). No claim is made about forms the system or a model was not built or trained on. The legacy out-of-distribution and wild suites (`eval/suites/formalizer-ood-v1`, `formalizer-wild-v1`) are archive and provenance and are no longer reported as suites: their rows are learning material, re-split by split group across train, dev and test of the three datasets with a fixed seed (`tools/eval/legacy-resplit.mjs`), which supersedes the earlier rule that rows of sealed legacy suites go only to the test. `eval/reports/current/` holds regenerable observations and `eval/reports/history/` holds archived numbers; never present a historical number as a current run.
10. Source rights are per asset, not per software licence: only source text recorded as cleared or permissive-attribution in `DS014-source-rights.md` may be ingested, exported or published, and unverified/restricted source text stays in the local source cache `datasets_sources/` and is never exported. By the owner's decision of 2026-09-28, corpora inspired by QQP, PAWS, ProofWriter, AmbigNQ, QA2D and SQuAD are released (`inspired-by-released`): they take structure, label types, phenomena and statistics, never text, and must pass `node tools/datasets/no-copy.mjs` (no 4-gram shared with a row's own source row, no 8-gram shared with any source, no ids in natural language). `datasets/SOURCES.md` lists each source, URL, licence and what was and was not taken; `tools/datasets/rights.mjs` supplies the provenance fields.
11. The corpora are JSONL-first. `datasets/<name>/{train,dev}.jsonl` (`bad_english`, `symbolic_english`, `neuro_english`, DS008 "Three datasets") or `datasets_archive/<corpus>/{train,dev}.jsonl` (the legacy corpora) and the sealed `eval/suites/<name>/test.jsonl` are the dataset artifacts; there is no case Markdown layer under `datasets/` (the Markdown authoring path was retired on 2026-09-28; each dataset's `README.md` states its rules, `datasets/SOURCES.md` its sources). A human reviews the data through the visual corpus audit (DS020), which is mounted at `/audit` on the main server (`npm start`, default `0.0.0.0:9999`, all interfaces) and requires the administrator session from `/admin`; its tabs are exactly `bad_english`, `symbolic_english` and `neuro_english` (purpose statement, row counts per split, filters, on-demand SymbolicLM and classifier checks) plus a secondary `archive / sources` tab; it re-executes cases on demand and appends verdicts to `eval/reports/current/audit/<dataset>.jsonl`. `node tools/datasets/audit-corpus.mjs --corpus <name>` is the machine audit: it writes `eval/reports/current/corpus-audit/<corpus>.json`, always fails closed on any structural invariant violation, and adds semantic-faithfulness, context-triviality, diversity and template-leakage checks whose failing set `--fail-on` selects (default: every error-severity check); `node check-datasets.mjs` runs it in report mode. Its procedure is `skills/corpus-audit/SKILL.md`.

The normative contracts behind these rules live in the DS set; where this file and a DS disagree, the DS is the source of truth for documented behavior.

Write persistent documentation, specifications, instructions, and code comments in clear English. Keep intentional linguistic data and exact quoted source material in their original language.

## Project journal

Every agent that starts, finishes or blocks a meaningful task, or records an owner decision, appends one event to `status/journal.jsonl` with `node tools/journal.mjs add --area <data|language|eval|training|server|docs|process> --state <started|progress|done|blocked|decision> --title "…" --detail "…" [--link <path>]…` (actor from `CHATSOP_ACTOR`). The journal is append-only: never edit or delete a line; correct a mistake with a new event. Experiment records (id, hypothesis, DS010 preregistration link, data version, status, results, conclusions) go to `status/experiments.json`. Major pieces of work are task records in `status/tasks.json` (owner side and agents side kept apart, DS010 "Tasks and topic notes").

Topic notes are the project's living history, next to the journal:
- Record every meaningful analysis, suggestion, result, observation, plan, open question and owner decision ALSO as a topic note: `node tools/notes.mjs add --topic <id> --kind <decision|suggestion|analysis|observation|experiment|result|plan|question|correction> --title "…" --body "…" [--link <path>]…` (topics in `status/topics.json`; include failed and restarted attempts with their numbers and logs).
- Notes are append-only like the journal: never edit or delete one; a correction is a new note with `--supersedes <note id>`, and both stay visible.
- The server's `/experiments` section (formerly `/project`, which redirects) is the living index of all of it: one page per task and experiment, the topic stacks, the reports, the timeline and the open questions, newest first; `/eval` shows the evaluation data behind any result.

## Early stopping of experiments

Do not spend compute on an experiment whose answer is already clear. Evaluations run in stages on stratified samples (for example 100, 300, then the full set) with a paired bootstrap interval after each stage; stop when the interval is decisive in the preregistered direction by a practically relevant margin, when a useful gain is already impossible (futility), or when the condition is broken (for example more than 20% unparsable or empty outputs on the first 100 rows). Training runs check progress at fixed points (dev loss plus a quick greedy decode on a stratified dev sample) and stop when clearly failing. Write the stopping rules into the preregistration (or record them as a deviation), and record every stop with its stage, numbers and reason in the journal, the topic notes, the experiment record and the task page. Bulk evaluation runs on the GPU when one is available; CPU speed is measured on a small sample only.

## Runtime Defaults

Node.js >=22.13 with `.mjs` modules, explicit imports, `node:` built-ins, async/await, and module-relative resources. Prefer built-ins and small auditable local code; record any necessary dependency in root `dependencies.md` or the owning skill's record. Keep Python only for indispensable model training and inference under `training/python/`; never install solvers, models, or packages, and never run GPU work merely to start the symbolic runtime. `docs/specs/DS001-coding-style.md` holds the full effective contract.

## Key Paths

`docs/index.html` is the HTML entry, `docs/runtime.html` explains execution, `docs/training.html` covers model/data boundaries, `docs/wiki.html` defines terminology, `docs/specs/` holds the authoritative DS set, and `docs/specsLoader.html?spec=matrix.md` opens its matrix. `lib/`, `sop/`, `memory/`, `reasoning/`, and `server/` separate runtime concerns; `config/` contains runtime configurations and the host ontology; `status/` holds the project journal and experiment registry; `tools/` owns conversion, validation and review tooling (`tools/datasets/` for data pipelines); `datasets/` holds only the three datasets `bad_english`, `symbolic_english` and `neuro_english` (owner decision of 2026-09-30, DS008 "Three datasets") and the owner-message collection `natural` (2026-10-01, DS008 "The natural collection"), `datasets_archive/` the legacy corpora that feed them (provenance and gold-SOP arbiter; old paths in `datasets_archive/PATH_ALIASES.json`, resolver `lib/dataset-paths.mjs`), with the raw source cache at `datasets_sources/`; `models/<model>/<run>/`, `eval/`, `examples/`, and `tests/` own their respective artifacts (demo/fixture SOP lives under `tests/fixtures/`). `probably_obsolete/` preserves archived evidence; `eval/reports/history/` preserves historical observations and `eval/reports/current/` fresh ones. Verify changed paths through executable behavior before reporting results.

No repository file (tracked, or untracked and not gitignored) may exceed 50 MB: large JSONL is stored as `<name>.part-NNN.jsonl` shards written and read through `lib/jsonl-shards.mjs` (Python: `training/python/common.py`), `node tools/shard-large-files.mjs` shards oversized files in place, and `node tools/shard-large-files.mjs --check` and `tests/file-size-limit.test.mjs` enforce the limit.
