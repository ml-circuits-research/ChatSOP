# material-to-sop dependencies and boundaries

- Node.js with built-in `fs`, `path`, `os`, `crypto`, `url`, and `util`; no `npm install`, Python, GPU, model, network call, or sibling skill required. The adapter expects a local ChatSOP checkout with ESM `.mjs` parser/ingest/runtime/repository exports, selected explicitly by `--project-root` for commands that use it. There is no embedded SOP engine or silent fallback. An incompatible project is rejected.
- Source inputs: UTF-8 `.txt` or `.md`, at most 2 MB; exact copied bytes are hashed with SHA-256. `.pdf`, `.docx`, HTML, network URLs, other binary containers, and automatic OCR are unsupported **by the CLI**. For conversion, the agent must use a verified external local extraction tool only if available, hash raw bytes, record URI/license/revision, tool version/options and output hash, and independently inspect normalized text against the original before using this CLI. Conversion provenance stays outside the CLI. The fixture license field `unresolved` is descriptive, not a grant.
- The workspace stores `source.txt`, `material.json`, `facts.json`, `curriculum.json`, `diagnosis-ID.json`, `registry.json`, `freeze-HASH.json`, and `publication-ID.json` as applicable. Source/fact/curriculum/diagnosis/freeze files are immutable for a workspace; candidate IDs are immutable. Registry updates change state. Keep workspace writable only by a trusted host and serialize concurrent commands per workspace; JSON hashes detect accidental changes, not malicious mutation. The publication command may mutate only the explicitly supplied ChatSOP `--state-root` and a new `--base`.
- Probe execution creates and removes separate OS temporary repositories; it uses a fixed date (`2026-01-01T00:00:00Z`) and does not write into the production repository. Its result is a runtime observation, not independent semantic review. Publication is not implicit in preparing, reviewing, diagnosing, probing, deciding, or freezing.
- `HARD` refers to a source-grounded, host-designated reviewer-approved logical implication in a stated domain, not necessarily a safety or policy guarantee. `DEFAULT`/`PLAUSIBLE` candidates are stored for examination but cannot be accepted/published by this adapter. A human or principal integrator can review; `reviewerKind` and `authorizerKind` preserve that distinction. Approval/authorization are asserted by host-supplied receipts and must be identity-checked outside this CLI; source documents and generators cannot self-approve. Historical published snapshots are not automatically revoked by registry retraction.
