# material-to-sop dependencies and boundaries

- Node.js built-ins run the CLI. Multi-source DOCX and HTML extraction require local Python 3 standard-library `zipfile`/`ElementTree`/`HTMLParser`; PDF extraction requires local `pdftotext`. This environment has Python 3 and `pdftotext`; `python3-docx` is absent and not required. No `npm install`, GPU, model, or network call is used. The SOP adapter requires a compatible local ChatSOP parser/ingest checkout selected by `--project-root`; no silent fallback.
- The legacy `prepare` accepts canonical UTF-8 TXT/MD at most 2 MB. `prepare-sources` supports canonical UTF-8 TXT/MD, main-document DOCX paragraphs, text-layer PDF pages, and static UTF-8 HTML blocks with per-source explicit rights, scope, raw byte limit, and passage limit. Raw input is capped at 20 MB and extracted text at 2 MB. Scanned/encrypted PDFs, OCR, DOCX footnotes/endnotes/comments/header/footer/drawings/fields/tracked changes, non-UTF-8 HTML, unknown formats, and unavailable adapters are not reliably supported. The `unresolved` license in legacy fixtures is not a rights grant. Source owner inspection of ambiguous PDF reading order and extraction meaning remains required.
- Multi-source workspaces isolate immutable raw copies and passage JSON in `datasets/knowledge/source/`, unapproved drafted facts in `datasets/knowledge/implicit/`, and disposable state in `temporary/`. Existing single-source artifacts (`source.txt`, `material.json`, `facts.json`, `curriculum.json`, `registry.json`, freezes, publication receipts) keep their original workflow. Keep workspaces private, serialize concurrent commands, and remember JSON hashes are integrity checks, not signatures. Only the existing explicitly authorized `publish` command mutates an explicitly selected ChatSOP runtime state root and a fresh base.
- Probe execution creates and removes separate OS temporary repositories; it uses a fixed date (`2026-01-01T00:00:00Z`) and does not write into the production repository. Its result is a runtime observation, not independent semantic review. Publication is not implicit in preparing, reviewing, diagnosing, probing, deciding, or freezing.
- `HARD` refers to a source-grounded, host-designated reviewer-approved logical implication in a stated domain, not necessarily a safety or policy guarantee. `DEFAULT`/`PLAUSIBLE` candidates are stored for examination but cannot be accepted/published by this adapter. A human or principal integrator can review; `reviewerKind` and `authorizerKind` preserve that distinction. Approval/authorization are asserted by host-supplied receipts and must be identity-checked outside this CLI; source documents and generators cannot self-approve. Historical published snapshots are not automatically revoked by registry retraction.
