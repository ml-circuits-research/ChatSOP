# InternalReasoningStepByStep: the questioning protocol as wires, driven by reasoning

Status: adopted by the orchestrator on 2026-10-02 (owner: protocol questions as wires in a base memory, code that builds SOP Lang, reasoning drives the questioning — metacognition and planning; a separate strategy compared in its own thread; LocalLLMStepByStep untouched). Plan by a planning agent (Fable); implementation by Claude Opus.

1. **Representation.** Seed base memory `config/knowledge/formalizer-protocol-v1/` (existing wire types only: predicate, fact, rule, default, action, integrity, goal, policy, procedure). Questions are `action` wires (`requires` preconditions, `adds` effects, `cost` = model calls); their text and choices are facts (`question_text`, `choice`, `choice_text`, `choices_from` for dynamic lists); slots are facts (`known kind`, `kind count`, `uses ?q ?st`, `place ?st ?role ?v`, `limit`, `except`, `rank`, `time_*`, `quantifier`, `definition`, `confirmed`). Turn observations come from structure and memory data (entity hints, numbers, dates, candidate statements, observed role fit, lexeme hits, procedure heads, validator problems), never from phrasing regex.
2. **Control.** Per step, the JS oracle (in process, deterministic, proofs) answers `select` over `open_slot`/`violation` (what is missing or inconsistent) and `plan` to the goal `formalized` (cheapest plan's first action = next question; `no_plan` from the start = honest `unclear relation_not_in_memory` with no model call); `explain` gives the trace. Contradictions are `integrity` violations that enable higher-cost re-ask actions; defaults give early exits and "enough confidence". Greedy Datalog choice is the budget fallback and an ablation; HTN and clingo/z3 are later ablations.
3. **Assembly.** Code maps established facts to the program of `lib/query-author/step-by-step/circuit.mjs` (imported read-only) and `validateQuery` is the only gate; validator problems become facts for the next round.
4. **Learning without training.** New question types and domain questions are wires added to the protocol memory (authoring skill, protocol lint, dry-run plan per kind); procedures can carry their own questions.
5. **Experiment** `eval-internal-reasoning-stepbystep-v1`: arms IR vs LocalLLMStepByStep method B vs CodingAgent (GLM), Qwen3-4B, the 89 protocol rows (+ 30 books items after stage 1); correct/wrong/unknown/invalid, questions, latency, engine ms per step, trace explanation quality; staged with stopping rules.
6. **Phases.** P0 protocol memory + lint + tests; P1 engine loop without a model; P2 parity with method B's coverage; P3 experiment; P4 authoring skill and docs.

Main risk: losing method B's literal cues on limits/superlatives — compensated with lexeme/entity data, never with regex.
