value

Creates a typed value from a literal or a bounded expression. It does not retrieve facts, decide a question, or put data in the repository.

Status and author: A formalizer may propose this wire under host policy; it is not by itself a memory write.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
datasingle; requiredA restricted expression: JSON double-quoted string, finite number, boolean, null, array/object, $wire result, or permitted operators/calls. A bare free name alone is rejected at parse time; runtime evaluates via the expression interpreter.

Execution and result

Strings use JSON quotes, not unquoted symbolic atoms. Expressions can compose values already produced by earlier wires. The result is the expression value; no world write occurs. A $wire that is unresolved blocks evaluation. This is not a proof packet and cannot impersonate a CNL source. Arithmetic, property access and calls obey the same bounded interpreter described on the jsEval page; value itself does not check allowJsEval.

Current SOP examples

Literal and structured data

@count value
  data 12

@description value
  data {route:"north", minutes:$count}

The first value is 12; the second is an object with a route label and numeric minutes. These are values, not stored claims.

Composition from a unique solve output

@trip query
  select ?minutes
  where duration(route_a, ?minutes)

@found solve
  query $trip
  output ?minutes one

@adjusted value
  data $minutes + 5

The query needs an admitted duration fact and a complete unique answer. If none or several are available, the output port is unavailable and @adjusted is blocked; it never guesses a duration.

Invalid or unsafe example

@bad value
  data arbitraryName

A free identifier is not a literal and is rejected by the value shape check.

Simplified syntax proposal (not implemented)

A smaller NL-to-query profile can use value only where an explicitly typed result is necessary; the discussed reduction is not an approved whitelist or a new parser. The current expression grammar remains in force.
