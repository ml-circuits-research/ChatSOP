pragmatic

A pragmatic wire says what a message does besides asking or stating: a greeting, thanks, an apology, a goodbye, a polite word, or an emotion such as frustration, confusion or urgency. The formalizer writes it in the same understanding step as the query (LLMDirect, or LocalLLMStepByStep from its first question), with basis llm; there is no separate word list or pattern system (AGENTS.md "No hardcoded understanding"). A signal is the system's perception of the message, never a fact about the world, never evidence, never stored and never carried to a later turn.

A message of courtesy or emotion only ("Hello!", "Thanks a lot!") is written as its pragmatic wires and nothing else (or with unclear kind no_request); the host answers it with a short reply rendered from the kinds, with no computation and no memory change (sop/pragmatic-text.mjs). Next to a query, the wires only set the tone of the answer: a courtesy phrase, an apology for the trouble after frustration, an offer to explain after confusion, a shorter answer under urgency. The runtime reports each wire in the packet as {id, kind, score, span, near, source, basis} and changes nothing else.

Every accepted keyword

KeywordCardinality / defaultAccepted value and concrete effect
kindExactly once; requiredOne kind of the closed set: greeting, closing, thanks, apology, politeness, urgency, frustration, anger, confusion, curiosity, joy, sadness, fear, disappointment, hedge, emphasis, profanity, offensive, irony_possible, confirmation_request (a tag question such as "right?"), topic_shift (a discourse marker such as "by the way") or unclassified (a pragmatic span that no strategy could name; the host does not emit it by default).
scoreAt most once; default 1The confidence as a decimal from 0 to 1 with at most three digits (0.8, 1); pragmatic_score_form otherwise. Signals under 0.5 do not change the reply.
spanAt most once; optionalOne nonempty JSON-quoted verbatim part of the message, at most 200 characters, that carries the signal (pragmatic_span_form; a span that is not in the message fails admission with pragmatic_span_not_in_message). Without span the signal describes the whole message.
nearAt most once; optionalnear $id: the wire the signal concerns (for example the query the frustration is about); one $id naming another, non-pragmatic wire of the same program (pragmatic_near_unknown otherwise).
sourceAt most once; optionalThe id of the strategy that wrote the signal, lowercase letters, digits and underscore (local_llm_step_by_step); descriptive only.
basisExactly once; requiredHow the signal was found, from a closed set: llm (the formalizer; what every strategy writes now), classifier, lexicon or pattern (kept for archived experiments). Descriptive only; the host never uses basis for trust.

Courtesy around a question

EN “Hi! Could you please tell me where Ana works? Thanks a lot!”

@p1 pragmatic
  kind greeting
  span "Hi"
  basis llm

@q query
  select ?x
  where match
    relation "works at"
    role subject "Ana"
    role object ?x
    polarity affirmed
  end

@p2 pragmatic
  kind thanks
  span "Thanks a lot"
  basis llm

The question is formalized as usual; the greeting and the thanks open the answer with a courtesy phrase and ask for no computation of their own.

A message that is only a greeting

EN “Hello!”

@p1 pragmatic
  kind greeting
  span "Hello"
  basis llm

No query and no unclear: the host replies "Hello! What would you like to know?" and the turn computes nothing.

An emotion about the question

EN “I already asked this twice: who manages Laura?”

@q query
  select ?x
  where match
    relation "manages"
    role subject ?x
    role object "Laura"
    polarity affirmed
  end

@p1 pragmatic
  kind frustration
  score 0.8
  span "I already asked this twice"
  near $q
  source local_llm_step_by_step
  basis llm

The answer opens with an apology for the trouble; the question itself is unchanged.

An unknown kind is rejected

The kinds are a closed set; a free label such as annoyed is not a kind.

@p1 pragmatic
  kind annoyed
  basis llm

A score is a decimal from 0 to 1

A confidence above 1 is rejected by the parser.

@p1 pragmatic
  kind thanks
  score 2
  basis llm
