reason

Runs a typed relational or numeric question with explicit inputs and returns a runtime result packet. It is the lower-level reasoning stage used by solve, which also creates link and output wires.

Status and author: A formalizer may propose this wire under host policy; it is not by itself a memory write.

Accepted fields

Single means at most once, repeatable means zero or more, and required means at least once at parse time. Other field names are rejected.

FieldCardinalityAccepted values and current behavior
queryAt most once; requiredsingle; conditionally required
constraintAt most once; requiredsingle; conditionally required
memoryAt most once; requiredsingle; optional on query route; ignored on constraint route
dataAt most once; requiredsingle; optional on query route; ignored on constraint route
backendAt most once; requiredsingle; optional, default auto
assumeAt most once; requiredsingle; optional on query route; ignored on constraint route
reasoningAt most once; requiredsingle; optional, default host reasoningStrategy (reference)
modeAt most once; requiredsingle; optional on query route, default deduce; ignored on constraint route
afterAt most once; requiredrepeatable; optional

Execution and result

Numeric route supplies declared variables/requirements to a solver. reference requires finite integer domains; advanced chooses Z3 if available, else JS finite fallback. Relational route joins local facts and optional retrieval memory; reference uses bounded JS Horn, advanced chooses Prolog for point queries when installed and JS otherwise. Explicit Prolog cannot handle interval queries. The result packet reports status, completeness, evidence/proof as applicable, ignored inputs and effective route. No output keyword is accepted here; use solve for materialized ports.

One qualified side effect is possible: with a repository/session and a nonhypothetical proof, the runtime reinforces verified observed claims actually used in the proof, never merely retrieved candidates. Reasoning does not assert new world facts.

Current SOP examples

Local relational deduction

@evidence fact
  holds parent(ana, bogdan)
  valid timeless

@q query
  where parent(ana, bogdan)

@r reason
  query $q
  data $evidence
  mode deduce

The reason result reflects the local admitted premise; no repository session is required for this route.

Finite numeric possibility

@limits constraint
  var ?x int 1 4
  require ?x > 2
  claim ?x == 3
  task possible

@r reason
  constraint $limits
  backend js

The result reports possibility relative to domain 1–4 and requirement x > 2; no output port is created.

Invalid or unsafe example

@q query
  where parent(ana, bogdan)

@c constraint
  claim 1 == 1

@bad reason
  query $q
  constraint $c

Exactly one of query or constraint is required. Runtime/parser shape validation rejects the combined route.
