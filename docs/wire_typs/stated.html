Wire index · assumed · unclear · query · model/host roles

stated

A stated wire is the small model's formalized report of one proposition that the user's message puts forward: the question itself or the assertions attached to it. It belongs to the model language. The model writes stated only when it is sure the claim comes from the message; anything it adds, infers, completes or presupposes is assumed. When in doubt, assumed. The normative contract is DS021.

The model has no context. Its prompt is the user's message only: no vocabulary, identifiers, knowledge or date. So a proposition is written as strings: a relation phrase, one line per role from a small closed inventory with the value as written in the message, the polarity, optional temporal expressions and the user's certainty. After the model, the host links the strings to its reviewed lexicon: the relation phrase and the set of role names select one predicate, the role values are resolved as entities with that predicate's argument types, and the temporal expressions are normalized. An unknown or ambiguous relation, entity or date becomes a host clarify; nothing is guessed. The result is the existing positional atom (works_at maria lab_alpha), so reasoners and oracles are unchanged. There is no quote, source or write field, and the statement is never recorded in the repository.

Every accepted keyword

KeywordCardinality / defaultAccepted value and concrete effect
relationExactly once; requiredOne JSON-quoted, nonempty relation phrase in the message's language or normalized, for example "works at" or "parent of". The host links it to a lexicon predicate by its labels, aliases, identifier and gloss after case and accent folding, dropping auxiliaries and articles and a plural or third-person -s. Unknown → host question; several predicates → the role set decides, otherwise host question.
roleRepeatable, 1 to 4 lines; required; a name at most oncerole NAME VALUE. NAME is one of the closed, context-free inventory subject, object, recipient, location, source, destination, instrument, time, topic (role_unknown, role_duplicate). VALUE is a JSON-quoted string exactly as the thing is mentioned in the message, or an integer; never a ?variable, $reference, ~handle or a bare identifier (proposition_not_ground). A statement must bind exactly the roles the linked predicate declares.
polarityExactly once; required, no defaultaffirmed or negated. negated is explicit (strong) negation and lowers to the not prefix; absence of evidence is never expressed this way.
validRepeatable, at most one line per form; optional; absent means timelessvalid on "TEXT", valid from "TEXT" or valid until "TEXT" (on excludes the others). TEXT is the temporal expression as written. The host normalizes ISO dates and UTC timestamps, a year, a year-month, a month name with a year (English or Romanian), now, today, yesterday and tomorrow (azi, ieri, mâine) against its clock; from starts at the period's start and until ends before the period's start. Anything else becomes a host question (time_form for a malformed line).
certaintyExactly once; requiredasserted: the user asserts it; lowered to a turn-local fact … source user used as evidence, not hypothetical, and carried to later turns in caller-owned conversation context. hedged ("I think …") and supposed ("suppose …", "if …"): user suppositions, lowered to fact … source assumption consumed through solve.assume; results that use them are hypothetical, and they are not carried.
speakerAt most once; default useruser or a JSON-quoted name as written: reported speech ("Ion says that …"). The claim stays attributed to the speaker, is used conditionally like supposed, and the packet renders it as "According to …".

Anchoring and reports

There is no quotation field; the anchor to the message is checked mechanically by the agent guard: every role value of a stated wire, and a non-user speaker, must appear in this turn's message after case, whitespace and accent folding, tolerating a small edit distance (0 for tokens up to 3 characters, 1 up to 7, otherwise 2, including an adjacent transposition) and a short inflected ending. Otherwise the turn is rejected with stated_value_not_in_message, and the model should use assumed or a query variable instead. The relation phrase is not anchored, because the model may normalize it. Exact duplicates are rejected (stated_duplicate); two contrary statements are accepted and the result reports the conflict. Every turn returns user_statements in the packet, each with the authored strings, the linked predicate and atom, validity, certainty, speaker, treatment (evidence or supposition) and a host-rendered statement such as You stated: works at (subject: Maria; object: Alpha Lab)., You supposed: … or According to Ana: ….

A user assertion and a question

@s1 stated
  relation "works at"
  role subject "Maria"
  role object "Alpha Lab"
  polarity affirmed
  certainty asserted

@q query
  where match
    relation "work at"
    role subject ?who
    role object "Alpha Lab"
    polarity affirmed
  end
  select ?who

"Maria works at Alpha Lab. Who works at Alpha Lab?" The host links both phrases to works_at, resolves "Maria" and "Alpha Lab" with that predicate's types, and answers maria, not hypothetically: the user said it. The fact exists only for this turn's execution and the conversation context; it is never stored or reinforced.

A dated supposition

@s1 stated
  relation "works at"
  role object "Alpha Lab"
  role subject "Maria"
  polarity affirmed
  valid from "2025"
  valid until "2026"
  certainty supposed

@q query
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    polarity affirmed
  end
  at "June 2025"

"Suppose Maria worked at Alpha Lab during 2025. Was she there in June 2025?" Role lines may appear in any order. The host normalizes the years and the month; the answer is conditional (hypothetical: true) and the rendering lists the supposition.

Reported speech on one day

@s1 stated
  relation "door open"
  role source "room A"
  role destination "room B"
  polarity negated
  valid on "3 March 2026"
  certainty asserted
  speaker "Ana"

"Ana says the door between room A and room B was not open on 3 March 2026." The date is copied as written; the model has no clock and never converts it, the host normalizes it. Without a question the turn only reports the statement; reported claims and suppositions apply only to a question in the same message, and only asserted user statements are carried.

Borderline cases

The boundary rule: stated only when the claim surely comes from the message; anything else is assumed. "Since Nera left the lab, who runs it now?" → stated (an assertion embedded in a question). "Is Ana still at Acme?" → assumed with basis implicature (the user did not assert the earlier state). "Rooms A and B are booked. Is room C free?" → two stated plus an assumed basis closure for room C. "I think the door is open" → stated certainty hedged. "Is the bank open?" with two banks → the model writes "the bank"; the host finds two entities and asks. A name mentioned only in an earlier turn is not in this message: the earlier asserted statement is carried by the host, so the model does not restate it. More borderline cases, with executed examples in English and Romanian, are in How the model writes.

Romanian, hedged

@s1 stated
  relation "lucra la"
  role subject "Ana"
  role object "Acme"
  polarity affirmed
  certainty hedged

@q query
  select ?place
  where match
    relation "locui în"
    role subject "Ana"
    role location ?place
    polarity affirmed
  end

"Cred că Ana lucrează la Acme. Unde locuiește?" "Cred că" ("I think") makes the statement hedged; the relation is written in the message's language and the values exactly as written (typos and missing diacritics included: "Ana lucreaza la Acme" would still give role object "Acme", and the host folds accents when it links).

Invalid model output

@bad stated
  holds works_at maria lab_alpha
  certainty asserted

A statement is written as keyword lines of strings; there is no packed atom, and the model does not know predicate identifiers.

@bad stated

  role subject "Maria"
  role object "Alpha Lab"
  certainty asserted
