fact

In general-runtime and trusted host circuits, a fact describes one supplied ground claim, its valid time and optional provenance. It constructs a value: it does not prove the claim, add it to memory, or imply publication. solve.data $claim may use the value only for that evaluation; remember is the separate operation that records an admitted claim in the current session.

Every accepted keyword

KeywordCardinality / defaultAccepted value and concrete effect
holdsExactly once; required[not ]predicate term1 [term2 [term3 [term4]]]; 1–4 whitespace-separated terms, no argument punctuation. Terms: canonical lowercase symbol, safe integer, JSON double-quoted string, $value reference. A ground relation or explicit negative relation is constructed; ?variables fail ground-fact lowering.
validExactly once; requiredtimeless or START END where endpoints are ISO dates, UTC timestamps, beginning or open. Inclusive start/exclusive end defines when the claim applies.
sourceAt most once; default userPlain remainder or JSON-quoted text; stored as claim-source metadata, not automatically verified authority. An omitted source silently records user, a trust class nobody wrote; write source explicitly. The exact value assumption is also a semantic switch, not only provenance text: such a fact may be consumed only through a solve/reason assume field (otherwise the run fails with assumption_fact_unconsumed or assumption_fact_not_evidence), is never used as evidence, is never stored (assumption_fact_not_recordable) and is never reinforced.
quoteAt most once; default emptyPlain remainder or JSON-quoted source excerpt; preserved as provenance metadata when recorded, not independently verified.
retentionAt most once; default normalnormal or pinned; pinned session recording requires host allowPin permission.

Local fact: no memory write

A supplied catalog card says book_a is on shelf_north. Each line has a different role: holds records the source claim in a value; where asks which book matches the shelf condition; solve.data passes the claim only to this evaluation; output requests a checked binding.

@catalog fact
  holds on_shelf book_a shelf_north
  valid timeless
  source "catalog card 17"

@question query
  where on_shelf ?book shelf_north
  select ?book
  mode select

@answer solve
  query $question
  data $catalog
  output ?book one

If the local claim is admitted, the unique result can bind $book to book_a; this is not independent verification and does not store the catalog card. An explicit negative claim has different meaning from absence of positive evidence:

@missing fact
  holds not on_shelf book_b shelf_north
  valid timeless
  source "catalog inventory"

@record remember
  input $missing
  scope session

This records the explicit negative statement in an authorized writable session. A missing positive fact alone would not establish the negative one.

Invalid: a fact is ground

@unsafe fact
  holds on_shelf ?book shelf_north
  valid timeless

The atom parses, but a fact cannot leave ?book unbound; use a query for unknown books. See shared atom syntax. The small model never writes a fact wire: it reports what the message says with stated and what it adds with assumed; the host lowers an asserted statement to a turn-local fact … source user and a supposition to fact … source assumption consumed only through assume.
