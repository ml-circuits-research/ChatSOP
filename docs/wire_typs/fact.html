fact

A SOP fact is a ground assertion with a validity interval and provenance. It produces a value, not a session write or proof. A formalizer can propose a fact from an explicitly admitted user statement; a coding agent can annotate reviewed source extracts; the host decides whether and where to persist them. This page explains the executable sop-agent-3 grammar.

Every supported field

Field / multiplicityAccepted grammar and effect
holds — exactly one, requiredpredicate(term, ...) or not predicate(term, ...), with 1–4 comma-separated terms. Predicate name is a canonical lower-case literal with digits/underscores; a dynamic $predicate(...) is not supported. A term may be a lower-case canonical symbol (including :/-), a safe integer, a JSON double-quoted string, or a $id reference resolved to a scalar. A ?variable parses but lowerFact rejects it: a fact must be ground. An explicit not records negative evidence, not an absence test. If the host supplies a schema, predicate existence, arity and argument types are checked. Entity values from resolve must be bound and type-compatible.
valid — exactly one, requiredtimeless or START END, an interval [START, END) with START < END. Endpoints may be YYYY-MM-DD, UTC YYYY-MM-DDTHH:mm:ssZ (optional .mmm), beginning or open. A point on the final boundary is outside the interval. The required field is checked by the parser; the interval's values are checked during lowering.
source — zero or one, default userLiteral text or JSON double-quoted string, decoded by unquote. Stored as claim-source metadata if asserted, not verified as a URL or authority. A $ spelling in this field is ordinary provenance text, not a wire dependency; give an actual source rather than a fabricated approval.
quote — zero or one, default empty stringLiteral text or JSON double-quoted string, decoded by unquote. An evidence excerpt retained in claim metadata when written; no automatic verification against the source. A $ spelling is ordinary text here, not a value dependency.
retention — zero or one, default normalThe lowering stage passes the field text through; a memory write accepts only normal or pinned. Pinned writes require host allowPin; neither option changes logical truth. Normal retention is subject to configured memory maintenance.

Value, provenance and time

The wire value contains kind:'fact', typed atom, validity interval, source, quote, retention and canonical SOP source. A $fact reference consumes this value. Although the parser recognizes ~fact as a handle reference, the current pack/assert reader does not accept a fact handle; consume $fact instead. ~ is not a generic mutable accumulator. solve may use local fact data without storage. assert writes to an authorized session and returns claim IDs; the write records a separate knownAt time. Claim identity derives from atom, validity, source and quote, so two sources can produce separate claims about the same atom. A query uses at/during for valid time and asof for the known-at view. Retrieved proof metadata depends on admitted, visible premises; mere source text is not itself proof.

Current syntax examples

This complete local circuit consumes a ground fact without persisting it. Assuming the displayed local premise is admitted, ?degrees can bind to 21 on September 20:

@reading fact
  holds temperature(room_a, 21)
  valid 2026-09-01 2026-10-01
  source "sensor record 17"
  quote "Operator recorded the reading"

@question query
  where temperature(room_a, ?degrees)
  select ?degrees
  at 2026-09-20

@answer solve
  query $question
  data $reading
  output ?degrees one

An explicit negative fact is distinct from a missing positive fact. The following writes one negative claim when a repository, session and allowWrite are available:

@closed fact
  holds not open(door_north)
  valid 2026-09-20 open
  source "operator report"

@save assert
  input $closed
  scope session

This atom is parser-valid but fails at lowering: ?degrees is a logical query variable, not an injected ground value.

@unsafe fact
  holds temperature(room_a, ?degrees)
  valid timeless

Simplified syntax proposal — not implemented

One design under discussion removes atom parentheses and commas while preserving separate explicit roles for $, ? and ~. The future small-model field inventory and meaning of ? have not been approved; this example cannot be parsed by today's grammar.

@reading fact
  holds temperature room_a 21
  valid 2026-09-01 2026-10-01
