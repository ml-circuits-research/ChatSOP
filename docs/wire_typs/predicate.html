Wire help / predicate

predicate

Declare a reviewed relation schema, including the ordered types of its arguments and its lexical forms. This is a host SOP ontology declaration consumed by Lexicon, not one of the 35 runtime circuit types. It is outside the small-formalizer output profile.

Every consumed keyword

KeywordCardinality and defaultValue grammar and meaning
argsRequired by Lexicon validation.One to four whitespace-separated argument-type names. Position matters: person organization differs from organization person. No parentheses or commas in this field.
descriptionOptional; default empty string.Plain explanatory text or a JSON-quoted string. It is not a rule body and does not execute.
labelOptional; repeatable.label LANGUAGE "surface". LANGUAGE has two or three lowercase ASCII letters. The surface is one nonempty token after quote-aware splitting; use JSON quotes for multiword text. The last label for a language supplies that language's display label; all forms remain lookup aliases.
aliasOptional; repeatable.alias LANGUAGE "surface", with the same language/text grammar. Adds a lookup form, not a new identity or semantic implication.
domainOptional; default null.Literal exact scope string. Use a simple canonical token; this field is read directly rather than evaluated as a reference or expression.

Identity, values, and validation

The header is @id predicate with the ordinary identifier spelling. The host loads the complete ontology through Lexicon. Its content hash and source provenance accompany resolution. Each canonical ID also supplies an und-language lookup form. A declaration produces an indexed ontology entry, not a $id runtime value. Use resolve to obtain a runtime value from an approved lexical lookup.

The extensible ontology parse route has no strict per-type SPEC field list. Lexicon reads the fields above; unrelated keywords can be ignored rather than rejected. Singleton fields are consumed through the first occurrence; repeated labels have the special behavior described above. Reviewers must reject unknown fields and duplicate singleton fields rather than assuming the runtime profile's strict checking applies here. No $, ?, or ~ evaluation occurs in these metadata fields.

Example: reviewed declaration

@works_at predicate
  args person organization
  description "The person works at the organization."
  label en "works at"
  domain staffing

Example: another declaration

@connected predicate
  args location location
  description "A directed connection from the first location to the second."
  label en "connected"

The first declaration fixes the person-first direction of works_at. The second fixes two location arguments; it does not assert symmetry or transitivity. Such inferences need explicit reviewed rules. Resolving a predicate alias returns its identity but cannot substitute a $reference into an atom head.

Invalid lexical form

@bad predicate
  args person organization
  label english "Example"

Lexicon rejects english because the language code must have two or three lowercase letters. This is ontology-consumer validation, not ordinary runtime-wire validation. A multiword surface without quotes likewise splits into too many tokens.

Authority and educational boundary

Only the host installs the reviewed ontology. A user document or model-generated declaration cannot approve a new identity, alias, predicate direction, or concept hierarchy. Unknown or ambiguous mentions require resolution/clarification, not an invented ontology entry. The punctuation-free circuit proposal does not authorize rewriting this metadata grammar without a separately agreed ontology contract.
