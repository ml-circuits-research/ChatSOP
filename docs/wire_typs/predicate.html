Wire help / predicate

predicate

Declare a reviewed relation schema, including the ordered, named roles of its arguments and its lexical forms. This is a host SOP ontology declaration consumed by Lexicon, not one of the runtime circuit types. The small model never authors it.

Every consumed keyword

KeywordCardinality and defaultValue grammar and meaning
roleRepeatable; one line per argument, in argument order. Either role lines or args are required.role NAME TYPE: NAME is one of the closed, context-free role inventory subject, object, recipient, location, source, destination, instrument, time, topic (ROLE_NAMES in sop/enums.mjs); TYPE is the argument type. The line order fixes the positional atom order. Names are unique within the predicate. The host uses these lines to link a model proposition (stated, assumed, a query match) whose relation phrase matches this predicate and whose role names fit it. A predicate without role lines is unnamed: with one or two arguments its positions are subject and object; with more it cannot be linked until roles are declared (the corpus audit flags unnamed roles).
argsAt most once; legacy form, required only when there are no role lines.One to four whitespace-separated argument-type names. Position matters: person organization differs from organization person. No parentheses or commas in this field. With role lines present, args must list exactly the same types in the same order, or Lexicon rejects the predicate.
descriptionOptional; default empty string.Plain explanatory text or a JSON-quoted string. It is not a rule body and does not execute.
labelOptional; repeatable.label LANGUAGE "surface". LANGUAGE has two or three lowercase ASCII letters. The surface is one nonempty token after quote-aware splitting; JSON double quotes are required for a multiword surface to remain one token; canonical generated/training snippets quote one-word surfaces too. See quoted text syntax. The last label for a language supplies that language's display label; all forms remain lookup aliases.
aliasOptional; repeatable.alias LANGUAGE "surface", with the same language/text grammar. Use a JSON string encoder for embedded double quotes and backslashes, not single or smart quote delimiters. Adds a lookup form, not a new identity or semantic implication.
readingOptional; repeatable, each value at most once.reading NAME with NAME one of class, occupation, attribute, identity, location, describe (COPULA_READINGS in sop/enums.mjs). The base memory declares here which of its predicates carry a reading of the copula, so the KnowledgeLinker never names a predicate itself: class ("Paris is a city", roles subject and object), occupation ("Ana is a doctor"), attribute ("Ana is happy"), identity ("Mark Twain is Samuel Clemens"), location ("Paris is in France", subject first and a second role) and describe (the facts of this predicate about a subject answer "Who is Ana?"; subject first). A reading other than these, a repeated one or an unsuitable role list is rejected by Lexicon. A memory that declares none answers a copula sentence with a precise question, not with an unknown relation.
describe_rankAt most once; optional; needs reading describe.A positive integer: the order of this predicate among the describe predicates (lowest first, then by id). The KnowledgeLinker reads "Who is Ana?" as the facts of every describe predicate about Ana, in this order.
domainOptional; default null.Literal exact scope string. Use a simple canonical token; this field is read directly rather than evaluated as a reference or expression.

Identity, values, and validation

The header is @id predicate with the ordinary identifier spelling. The host loads the complete ontology through Lexicon. Its content hash and source provenance accompany resolution. Each canonical ID also supplies an und-language lookup form. A declaration produces an indexed ontology entry, not a $id runtime value. Use resolve to obtain a runtime value from an approved lexical lookup.

Actual enforcement: the parser applies the strict ontology SPEC (ONTOLOGY_SPEC.predicate in sop/parser.mjs): an unknown field such as a misspelling is rejected (Unsupported field … on predicate) and a repeated singleton (args, description, domain) is rejected (Duplicate …). Lexicon additionally rejects a malformed label/alias line (Use label/alias LANGUAGE "surface") or an empty surface, a malformed role line (Use role NAME TYPE), a repeated role name, args that disagree with the role types, and a predicate without one to four arguments (Predicate needs 1..4 argument types). No $, ?, or ~ evaluation occurs in these metadata fields.

Example: reviewed declaration

@works_at predicate
  role subject person
  role object organization
  description "The person works at the organization."
  label en "works at"
  domain staffing

Example: another declaration

@connected predicate
  args location location
  description "A directed connection from the first location to the second."
  label en "connected"

The first declaration fixes the person-first direction of works_at and maps it to subject and object, so a model proposition relation "works at" with role subject "Maria" and role object "Acme", in any order, is linked and lowered to works_at maria acme. The second uses the legacy args form, whose two positions are subject and object. The second fixes two location arguments; it does not assert symmetry or transitivity. Such inferences need explicit reviewed rules. Resolving a predicate alias returns its identity but cannot substitute a $reference into an atom head.

Example: copula readings

@instance_of predicate
  role subject entity
  role object entity
  reading class
  reading describe
  describe_rank 1

@located_in predicate
  role subject entity
  role location entity
  alias en "be in"
  reading location

instance_of carries the class reading and is the first description predicate; located_in carries the location reading. A model proposition relation "be" with role subject "Ana" and role object "a doctor" is then linked to the predicate that declares the occupation or class reading, and "Who is Ana?" (role object ?x) to the facts of the describe predicates. See DS021, "KnowledgeLinker: the copula and the relation lexicon".

Invalid lexical form

@bad predicate
  args person organization
  label english "Example"

Lexicon rejects english because the language code must have two or three lowercase letters. This is ontology-consumer validation, not ordinary runtime-wire validation. A multiword surface without quotes likewise splits into too many tokens.

Invalid field

@bad predicate
  role subject person
  role object organization
  arity 2
@bad predicate
  role employee person
  role employer organization
@bad predicate
  role subject entity
  role object entity
  reading wizard

Predicate-specific role names are rejected: the context-free model only knows the closed inventory.

The strict ontology SPEC rejects every keyword it does not list.

Authority and educational boundary

Only the host installs the reviewed ontology. A user document or model-generated declaration cannot approve a new identity, alias, predicate direction, or concept hierarchy. Unknown or ambiguous mentions require resolution/clarification, not an invented ontology entry. The runtime atom cutover does not change this host ontology metadata grammar.

Knowledge language: predicate

In the knowledge language a predicate declares a relation by args with roles and types, not by role lines; its id is the relation name. The tables and examples of this section are about the knowledge form, written from a source and checked by sop/knowledge/; the sections above describe the host-circuit form. Anchors of this section's fields start with kfield-. The language manual is the section "Knowledge wires" of DS004.

Other field names are rejected (unknown_field). The table is generated from sop/knowledge/grammar.mjs.

FieldCardinalityAccepted values and behavior
argsAt most once; requiredrole:type entries, or none for arity 0 (a state flag such as business_hours). Types: entity integer text time value. Roles: subject object recipient location source destination instrument time topic, at most one argument per role; give a role to every argument or to none (args_mixed_roles, duplicate_role; without roles the warning args_without_roles). At most six arguments.
closedAt most once; optionaltrue or false (default false). true says the retained view holds every fact of the relation; it is what makes absent, counts, sums and every meaningful. Declare it only when the source says the list is exhaustive, and quote that sentence in description. The host accepts closedness after review, over an archived or pinned view.
keyAt most once; optionalAn argument position (1 to the arity) that determines the rest: a lint, two facts with the same key and different remainders and no validity give the warning key_violation.
transitiveAt most once; optionaltrue or false, arity 2 only (bad_transitive): an advisory hint for routing to a closure template.
inverseAt most once; optionalA lowercase symbol: the name of the inverse relation (an advisory hint).
unitAt most once; optionalText: the unit of a numeric argument.
readingRepeatable, each value at most once; optionalOne of class occupation attribute identity location describe: a copula reading the relation carries (bad_enum otherwise). It lets the base memory, not the engine, say which predicate answers "Ana is a doctor" (occupation), "Paris is in France" (location) or "Who is Ana?" (describe).
describe_rankAt most once; optionalA positive integer, the order among the describe predicates (lowest first).
descriptionAt most once; optionalText: what the relation means, and for a closed relation the source sentence that says the list is exhaustive.

What it is for

The declaration fixes the arity, which position is the subject and which the object, and the types, so the checker catches an orientation slip (works_at firm person against works_at person firm) when the knowledge is written. The roles are also the bridge between the two surfaces: the model writes role subject "Ann" and role object "Alpha Lab", the host lexicon maps the relation phrase to the predicate, and the predicate's roles place each string in its position. Declare a predicate before its first fact.

Examples

@located_in predicate
  args subject:entity location:entity
  description "Atlas p.12 lists the cities of each country"

@f1 fact
  holds located_in paris france
  source "Atlas p.12"
@f2 fact
  holds located_in lyon france
@q query
  where located_in ?city france
  select ?city

Example: copula readings in the knowledge form

@occupation predicate
  args subject:entity object:entity
  reading occupation
  reading describe
  describe_rank 2

@f1 fact
  holds occupation ana doctor

Invalid: a constant of the wrong type

@located_in predicate
  args subject:entity location:entity
@f1 fact
  holds located_in paris 12
@p predicate
  args subject:entity object:entity
  reading wizard

Common mistakes

  1. Arguments in the wrong order, or without roles and types.
  2. A seventh argument: reify the event instead.
  3. closed true without a source sentence that says the list is complete.
  4. A predicate and a fact sharing one id: ids and relation names share one namespace.
