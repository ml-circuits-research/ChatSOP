Wire help / predicate

predicate

Declare a reviewed relation schema, including the ordered, named roles of its arguments and its lexical forms. This is a host SOP ontology declaration consumed by Lexicon, not one of the runtime circuit types. The small model never authors it.

Every consumed keyword

KeywordCardinality and defaultValue grammar and meaning
roleRepeatable; one line per argument, in argument order. Either role lines or args are required.role NAME TYPE: NAME is one of the closed, context-free role inventory subject, object, recipient, location, source, destination, instrument, time, topic (ROLE_NAMES in sop/enums.mjs); TYPE is the argument type. The line order fixes the positional atom order. Names are unique within the predicate. The host uses these lines to link a model proposition (stated, assumed, a query match) whose relation phrase matches this predicate and whose role names fit it. A predicate without role lines is unnamed: with one or two arguments its positions are subject and object; with more it cannot be linked until roles are declared (the corpus audit flags unnamed roles).
argsAt most once; legacy form, required only when there are no role lines.One to four whitespace-separated argument-type names. Position matters: person organization differs from organization person. No parentheses or commas in this field. With role lines present, args must list exactly the same types in the same order, or Lexicon rejects the predicate.
descriptionOptional; default empty string.Plain explanatory text or a JSON-quoted string. It is not a rule body and does not execute.
labelOptional; repeatable.label LANGUAGE "surface". LANGUAGE has two or three lowercase ASCII letters. The surface is one nonempty token after quote-aware splitting; JSON double quotes are required for a multiword surface to remain one token; canonical generated/training snippets quote one-word surfaces too. See quoted text syntax. The last label for a language supplies that language's display label; all forms remain lookup aliases.
aliasOptional; repeatable.alias LANGUAGE "surface", with the same language/text grammar. Use a JSON string encoder for embedded double quotes and backslashes, not single or smart quote delimiters. Adds a lookup form, not a new identity or semantic implication.
domainOptional; default null.Literal exact scope string. Use a simple canonical token; this field is read directly rather than evaluated as a reference or expression.

Identity, values, and validation

The header is @id predicate with the ordinary identifier spelling. The host loads the complete ontology through Lexicon. Its content hash and source provenance accompany resolution. Each canonical ID also supplies an und-language lookup form. A declaration produces an indexed ontology entry, not a $id runtime value. Use resolve to obtain a runtime value from an approved lexical lookup.

Actual enforcement: the parser applies the strict ontology SPEC (ONTOLOGY_SPEC.predicate in sop/parser.mjs): an unknown field such as a misspelling is rejected (Unsupported field … on predicate) and a repeated singleton (args, description, domain) is rejected (Duplicate …). Lexicon additionally rejects a malformed label/alias line (Use label/alias LANGUAGE "surface") or an empty surface, a malformed role line (Use role NAME TYPE), a repeated role name, args that disagree with the role types, and a predicate without one to four arguments (Predicate needs 1..4 argument types). No $, ?, or ~ evaluation occurs in these metadata fields.

Example: reviewed declaration

@works_at predicate
  role subject person
  role object organization
  description "The person works at the organization."
  label en "works at"
  domain staffing

Example: another declaration

@connected predicate
  args location location
  description "A directed connection from the first location to the second."
  label en "connected"

The first declaration fixes the person-first direction of works_at and maps it to subject and object, so a model proposition relation "works at" with role subject "Maria" and role object "Acme", in any order, is linked and lowered to works_at maria acme. The second uses the legacy args form, whose two positions are subject and object. The second fixes two location arguments; it does not assert symmetry or transitivity. Such inferences need explicit reviewed rules. Resolving a predicate alias returns its identity but cannot substitute a $reference into an atom head.

Invalid lexical form

@bad predicate
  args person organization
  label english "Example"

Lexicon rejects english because the language code must have two or three lowercase letters. This is ontology-consumer validation, not ordinary runtime-wire validation. A multiword surface without quotes likewise splits into too many tokens.

Invalid field

@bad predicate
  role subject person
  role object organization
  arity 2
@bad predicate
  role employee person
  role employer organization

Predicate-specific role names are rejected: the context-free model only knows the closed inventory.

The strict ontology SPEC rejects every keyword it does not list.

Authority and educational boundary

Only the host installs the reviewed ontology. A user document or model-generated declaration cannot approve a new identity, alias, predicate direction, or concept hierarchy. Unknown or ambiguous mentions require resolution/clarification, not an invented ontology entry. The runtime atom cutover does not change this host ontology metadata grammar.
