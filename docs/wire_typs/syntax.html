Shared syntax and references

The executable sop-agent-3 grammar is line-oriented. A wire type owns its field vocabulary; accepting arbitrary text after a keyword does not authorize arbitrary execution. Use the individual wire pages for field-specific rules.

Headers, fields, and blocks

ConstructExecutable grammarRejected or different meaning
Header@name type at column one. The name begins with an ASCII letter and continues with letters, digits, or underscores. Type names are case-sensitive.Duplicate names; reserved names constructor, prototype, __proto__; unknown runtime types; extra header tokens.
FieldExactly two spaces, a permitted keyword, then its value. Keyword and values are separated by whitespace.Tabs or four-space field indentation outside a block; unknown keywords; repeated single-valued fields.
Repeated fieldWrite a separate line for each occurrence, in source order, only for keywords declared repeatable.Repeating select does not create a larger projection. Repeating result does not create multiple inputs.
Multiline valueWrite body |, followed by content indented at least four spaces. The parser strips four spaces and trailing block whitespace.A code body is not implicitly executable. Its owning type determines how it is consumed.
CommentsA line whose first non-whitespace character is # is ignored; blank lines are ignored outside values.There is no general trailing inline-comment syntax. Appending # text may change a field's value.

The parser defaults to at most 2,048 wires and 1 MiB of input. Runtime budgets and field consumers impose further limits. Header order is not a substitute for an explicit data or effect dependency.

Atoms and argument values

An atom has an optional not, a lowercase predicate name, then one to four whitespace-separated terms: [not ]predicate term1 [term2 [term3 [term4]]]. No parentheses or commas delimit the atom. Prefix not expresses explicit negative evidence, not failure to find positive evidence; not cannot be a predicate name. JSON double-quoted string terms preserve spaces, commas, parentheses and JSON escapes.

@positive fact
  holds works_at maria acme
  valid timeless

@negative fact
  holds not works_at ion acme
  valid timeless

@question query
  where works_at ?person acme
  select ?person
TermExampleBoundary
Canonical symbolroom_aStarts with a lowercase ASCII letter; following characters may include lowercase letters, digits, underscore, colon, or hyphen. Predicates have the narrower lowercase-letter/digit/underscore spelling.

String"North room"JSON string spelling and escaping. A quoted string with variable-shaped content remains subject to the semantic consumer; do not use quoting to smuggle a logic variable into a ground fact. Adjacent quoted terms require whitespace.

No nested function terms, zero-argument atoms, arbitrary expressions inside atom arguments, or handle arguments ~definition are supported by this atom grammar.

Four sigils with different jobs

FormMeaningWhere it works
@idDeclares a wire.Header only; not the way to consume its result.
$idConsumes the produced value and creates an execution dependency.Fields that consume references or expressions; exact scalar/collection rules depend on the field.
?xA logic variable; in an output declaration, the name of a requested output port.Atoms, projections, supported expressions, and output declarations. It is not general text or context injection.
~idNames a declaration or reviewed definition without demanding its ordinary produced value.Object-consuming fields, such as expand.using or declaration collections. It is not a general mutable variable or an arbitrary operation handle.

The graph validator checks reference existence and rejects cyclic value dependencies, including dependencies through output ports. Names inside quoted text are not executable references. The text and quote fields, and provenance source fields except analogize.source, are excluded from dependency scanning. Template and procedure bodies acquire their dependencies through controlled expansion.

Handle restriction: the object reader accepts rule, pattern, hypothesis, action, goal, trace, policy, theory, template, and procedure handles. Although a reference such as ~factName can pass graph existence checks, this reader does not lower fact handles. Pass the computed $factName to pack, remember, or local data inputs instead.

Explicit Boolean groups: all, any, end

Executable query.where, query.filter, constraint.require, and constraint.claim accept native nested blocks. all requires every child; any accepts an alternative; end closes the nearest group. Every group must have at least one child, with at most 32 nested groups. Repeated fields remain an implicit conjunction. Indentation communicates nesting, but the end markers determine it. Inside where blocks, leaves use the current atom grammar; inside filter/require/claim blocks, leaves use comparison expressions. Boolean grouping needs no parentheses or operator precedence. This change does not replace atom punctuation or arithmetic syntax.

@q query
  where all
    works_at ?person ?organization
    any
      located_in ?organization france
      located_in ?organization germany
    end
  end
  select ?person ?organization

Each match binds person and organization together. Repeated variable names constrain the same assignment; their scope is this query, not unrelated wires. Variables selected or used in filters must be guaranteed by every alternative or by another shared conjunct; a branch-local variable cannot become an occasionally missing output field. A later solve with output ?matches rows exports one array of correlated assignments, not separate arrays or one wire per match. See the result-shape intuition and engine responsibilities.

Outputs are not arbitrary assignments

@q query
  where works_at ?person acme
  select ?person

@s solve
  query $q
  output ?person one

@copy value
  data $person

This fragment requires an available memory view for solve. It reserves the output name person and makes $person dependent on the solve result. one must obtain a justified unique value; zero, multiple, conflicting, or incomplete answers do not permit selecting an arbitrary value. The runtime materializes a binding; the author does not write that internal wire. The value wire is a runtime illustration, not part of the three-type model-authored declarative grammar.

Quoted text: accepted input and canonical output

Use ASCII double quotes to delimit a text literal. Preserve a person's supplied spelling and capitalization: "Maria Ionescu" is a name mention, not an automatically identified person. A reviewed resolve operation can identify that mention; a consumer then uses $person. Capital letters do not determine whether a token is a variable, entity, or literal.

PositionAccepted inputCanonical generated spelling
Whole-line text field: resolve.text, clarify.text, fact.quoteQuotes are optional because the field consumes the remainder of the line. text Maria Ionescu is accepted by resolve.text "Maria Ionescu". Quote free text consistently, including one-word names such as text "Maria".
One text argument in a whitespace-tokenized fieldQuotes are required for a multiword text argument, such as the surface in label en "Maria Ionescu".Quote the text argument, not its language code or the surrounding field keyword.
Active reference or logic variable$person, ?country, ~procedure, where the owning field allows that reference kind.Leave the reference unquoted. "$person" in a text field is literal text, not the person's identity.
Structural or typed tokensource user, kind entity, language en, canonical symbol maria, numeric 12.Do not turn enum values, canonical identifiers, or numbers into free text by mechanically adding quotes. Follow the field grammar.

These two executable snippets provide the same resolve.text value; the host must still supply a reviewed lexicon. The first is the canonical authoring form. The second illustrates accepted input, not an alternative training target to mix into the corpus.

@person resolve
  text "Maria Ionescu"
  language en
  kind entity
  type person
@person resolve
  text Maria Ionescu
  language en
  kind entity
  type person

Escapes and inert text

Use \" for an embedded double quote and \\ for a literal backslash. Encode strings with a JSON string encoder so control characters and escapes are not assembled by hand. Single quotes and typographic quotes are not delimiters. Names and quotations retain their original language even though documentation prose is English.

@question clarify
  text "Which \"Maria Ionescu\" do you mean? The tokens $person, ?country and ~record are literal here; path C:\\records."

This clarify.text decodes to a message containing double quotes, one backslash in the path, and the literal sigils. It does not create dependencies on person, country, or record. For a fact.quote, compare the decoded text with the exact source span: the escape spelling is not part of the quotation.

When putting SOP inside a JSONL row, first form the SOP string, then serialize the containing JSON object. That transport adds its own escaping. Do not copy a JSONL-escaped value directly into a plain SOP file or decode it twice. A raw newline must not accidentally start another field; use supported multiline text or JSON escapes appropriate to the consumer.

Atom boundary

Quoted strings are atom terms, not name resolution. The lowered atom representation does not retain whether variable-shaped text was quoted: "?country" can be interpreted as a logic variable rather than a ground string. Keep arbitrary source quotations in text/quote fields, not as a workaround for atom typing. One to four terms are required; parent(maria, ion), parent maria, ion, adjacent quoted tokens and multiline atom text are rejected.

@old fact
  holds parent(maria, ion)
  valid timeless

The former parenthesized atom spelling is intentionally invalid. The valid spelling is parent maria ion.

Strings, dates, and execution checks

Text consumers commonly accept a bare remainder or a JSON-quoted string through unquote. Token-list consumers use a different rule: a multiword string must be quoted to stay one token. Never assume all fields share the same tokenizer. Dates use ISO date or UTC timestamp spelling. Validity intervals are start-inclusive and end-exclusive; timeless spans all time. at/during describe valid time; asof describes the transaction-time knowledge view.

Validation occurs in stages: parsing checks headers/fields and selected local forms; graph validation checks dependencies; lowering checks groundness, schema types, bound variables, and numeric domains; execution checks permissions, cardinality, supported backends, and result provenance. An invalid example on a wire page identifies which stage rejects it. A parser-valid snippet is not by itself a proof of runtime success.
