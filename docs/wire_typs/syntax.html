Shared syntax and references

The sop-agent-3 grammar is line-oriented. A wire type owns its field vocabulary; accepting arbitrary text after a keyword does not authorize arbitrary execution. Use the individual wire pages for field-specific rules.

Headers, fields, and blocks

ConstructExecutable grammarRejected or different meaning
Header@name type at column one. The name begins with an ASCII letter and continues with letters, digits, or underscores. Type names are case-sensitive.Duplicate names; reserved names constructor, prototype, __proto__; unknown runtime types; extra header tokens.
FieldExactly two spaces, a permitted keyword, then its value. Keyword and values are separated by whitespace.Tabs or four-space field indentation outside a block; unknown keywords; repeated single-valued fields.
Repeated fieldWrite a separate line for each occurrence, in source order, only for keywords declared repeatable.Repeating select does not create a larger projection. Repeating result does not create multiple inputs.
Multiline valueWrite body |, followed by content indented at least four spaces. The parser strips four spaces and trailing block whitespace.A code body is not implicitly executable. Its owning type determines how it is consumed.
CommentsA line whose first non-whitespace character is # is ignored; blank lines are ignored outside values.There is no general trailing inline-comment syntax. Appending # text may change a field's value.

The parser defaults to at most 2,048 wires and 1 MiB of input. Runtime budgets and field consumers impose further limits. Header order is not a substitute for an explicit data or effect dependency.

Atoms and argument values

An atom has a literal predicate name, parentheses, and one to four comma-separated arguments. Prefix not expresses explicit negative evidence; it does not mean failure to find positive evidence.

@positive fact
  holds works_at(maria, acme)
  valid timeless

@negative fact
  holds not works_at(ion, acme)
  valid timeless

@question query
  where works_at(?person, acme)
  select ?person
TermExampleBoundary
Canonical symbolroom_aStarts with a lowercase ASCII letter; following characters may include lowercase letters, digits, underscore, colon, or hyphen. Predicates have the narrower lowercase-letter/digit/underscore spelling.
Integer-12Safe integer. Decimal atom arguments are not accepted by this parser profile.
String"North room"JSON string spelling and escaping. A quoted string with variable-shaped content remains subject to the semantic consumer; do not use quoting to smuggle a logic variable into a ground fact.
Value reference$companyThe producer must supply a value compatible with the predicate argument schema. No dynamic predicate heads.
Logic variable?personAllowed in logical goals and rules, not in ground facts. The query projection must select variables bound in its where atoms.

No nested function terms, zero-argument atoms, arbitrary expressions inside atom arguments, or handle arguments ~definition are supported by this atom grammar.

Four sigils with different jobs

FormMeaningWhere it works
@idDeclares a wire.Header only; not the way to consume its result.
$idConsumes the produced value and creates an execution dependency.Fields that consume references or expressions; exact scalar/collection rules depend on the field.
?xA logic variable; in an output declaration, the name of a requested output port.Atoms, projections, supported expressions, and output declarations. It is not general text or context injection.
~idNames a declaration or reviewed definition without demanding its ordinary produced value.Object-consuming fields, such as expand.using or declaration collections. It is not a general mutable variable or an arbitrary operation handle.

The graph validator checks reference existence and rejects cyclic value dependencies, including dependencies through output ports. Names inside quoted text are not executable references. The text and quote fields, and provenance source fields except analogize.source, are excluded from dependency scanning. Template and procedure bodies acquire their dependencies through controlled expansion.

Handle restriction: the object reader accepts rule, pattern, hypothesis, action, goal, trace, policy, theory, template, and procedure handles. Although a reference such as ~factName can pass graph existence checks, this reader does not lower fact handles. Pass the computed $factName to pack, assert, or local data inputs instead.

Outputs are not arbitrary assignments

@q query
  where works_at(?person, acme)
  select ?person

@s solve
  query $q
  output ?person one

@copy value
  data $person

This fragment requires an available memory view for solve. It reserves the output name person and makes $person dependent on the solve result. one must obtain a justified unique value; zero, multiple, conflicting, or incomplete answers do not permit selecting an arbitrary value. The runtime materializes a binding; the author does not write that internal wire. The value wire is a runtime illustration, not part of the proposed small-model core.

Strings, dates, and execution checks

Text consumers commonly accept a bare remainder or a JSON-quoted string through unquote. Token-list consumers use a different rule: a multiword string must be quoted to stay one token. Never assume all fields share the same tokenizer. Dates use ISO date or UTC timestamp spelling. Validity intervals are start-inclusive and end-exclusive; timeless spans all time. at/during describe valid time; asof describes the transaction-time knowledge view.

Validation occurs in stages: parsing checks headers/fields and selected local forms; graph validation checks dependencies; lowering checks groundness, schema types, bound variables, and numeric domains; execution checks permissions, cardinality, supported backends, and result provenance. An invalid example on a wire page identifies which stage rejects it. A parser-valid snippet is not by itself a proof of runtime success.

Simplified syntax proposal

The proposed small-model surface retains @id type, keyword-led lines, and the sigils. It replaces atom punctuation with positional terms separated by spaces:

@q query
  where works_at ?person acme
  select ?person

The exact scope of ? as a produced contextual wire, ~ as a named internal accumulator, and multiline/code boundaries require an explicit contract. No part of this help silently grants those meanings to sop-agent-3. Removing atom punctuation does not require additional wires and does not remove punctuation from quoted data or coding-agent JavaScript.
