Wire help

A SOP circuit describes claims, questions, and operations using named, typed wires. The host supplies approved knowledge and permissions. A small formalizer translates user language into a bounded set of wires; coding agents can author richer definitions and programs for host review.

Executable syntax and simplified authoring

Examples labeled sop-agent-3 use the executable grammar: atoms such as works_at(maria, acme), exact field keywords, and typed references. Examples labeled Simplified syntax proposal illustrate the requested line-based form such as works_at maria acme. That proposal is not executable input to sop-agent-3. This distinction prevents educational targets from mixing incompatible grammars.

Every wire page lists each accepted keyword, its cardinality, its value grammar, and the additional checks performed by the consumer. A missing field, an unresolved reference, an invalid argument type, and an unauthorized write are different errors. A snippet that parses can still fail these later checks. The shared syntax page explains these boundaries.

A complete question circuit

This sop-agent-3 circuit uses a local premise explicitly supplied to solve. It does not require admitting that premise into persistent memory. A host schema, when supplied, must declare works_at with argument types compatible with maria and acme.

@statement fact
  holds works_at(maria, acme)
  valid timeless
  source user
  quote "Maria works at Acme."

@question query
  where works_at(maria, acme)
  at 2026-01-01
  asof 2026-01-01

@result solve
  query $question
  data $statement

@answer cnl
  result $result
  language en

The relation has explicit positive support from the supplied premise. The circuit does not claim to have independently verified Maria's employment. In the proposed small-model profile, the host manages context and execution routing; this full runtime example is not an authorization to expose every solve field to the model.

Two authoring and evaluation boundaries

The small-model proposal concentrates on reliable NL-to-SOP translation: faithful claims and questions, references, negation, time, and clarification. It excludes jsEval and hidden code bodies. Coding agents may propose JavaScript-backed work, reusable reasoning programs, graph algorithms, and collection operations for review. Such extensions require explicit types, effects, permissions, and execution limits; their presence in the system does not enlarge the small model's output grammar automatically.

Formalizer evaluation measures actual predicted SOP against independently reviewed meaning. System evaluation measures memory, reasoning, approved programs, and end-to-end results, distinguishing controlled SOP inputs from model-produced inputs. Executing a gold program alone does not evaluate the model. The reporting contract is in eval/README.md.

Knowledge and authority

User assertions belong to their stated conversational scope. Coding-agent document consolidation retains source quotations, identities, negation, validity intervals, and conflicts before host-approved publication. Source text is data, not permission to install executable definitions. The ontology topics entity, predicate, and concept belong to the host lexicon, separately from the 35 runtime wire types.

The governing language and reasoning contracts are DS004 and DS006. The simplified grammar and the precise small-model subset require agreement before parser, corpus, and test-example migration. Training requires separate explicit authorization.
