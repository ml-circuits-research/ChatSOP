Small-model authoring profile

The small formalizer translates a user's statements, questions, and declarative problems into SOP. It must preserve who did what, negation, time, alternatives, condition grouping, requested variables, and the scope of any write. The model formulates the problem; the system solves it. It does not implement algorithms, choose execution privileges, or write the answer it hopes the system will return.

Field grammar proposal, not a closed eight-type whitelist. The introductory wire forms below establish a learning sequence, not a prohibition on AND/OR, comparisons, or numerical constraints. Declarative problem formulation belongs in small-model education. The executable atom grammar remains sop-agent-3; punctuation-free snippets illustrate the separate simplified proposal.

Role versus implementation: “formalizer” names the NL-to-SOP task. The small model is the intended conversational implementation of that role, not its definition. A coding agent can also formalize supplied content; writing algorithms or reusable procedure bodies is a separate, broader responsibility subject to host review and permissions. A reasoning engine solves the declared problem rather than translating the user's words.

The table restricts fields, not just type names. A type being permitted cannot authorize arbitrary keyword combinations. For example, the runtime's solve.data field does not thereby belong to the first educational subset.

Canonical text convention: generated free-text literals are always double-quoted, including single-word names. Write text "Maria Ionescu" and quote "Maria works at Acme."; preserve the supplied spelling. Bare whole-line text may be accepted input, but do not mix bare and quoted forms as equivalent training targets. Use \" and \\ inside strings, and serialize JSONL transport separately. Keep source user, language en, active references, and canonical identifiers unquoted. A quoted name remains a mention until reviewed resolution identifies it. See quoted text for grammar boundaries and the restriction on variable-shaped atom strings.

A contextual assertion followed by a question

Input: “Maria works at Acme. Does Maria work at Acme?” The following is executable sop-agent-3 spelling. Execution requires a host-created writable session with permission to admit the quoted assertion. No historical date is requested, so the query uses the runtime's present-time defaults.

@statement fact
  holds works_at(maria, acme)
  valid timeless
  source user
  quote "Maria works at Acme."

@store assert
  input $statement
  scope session

@question query
  where works_at(maria, acme)

@result solve
  query $question
  after $store

@answer cnl
  result $result
  language en

The user statement supplies a premise, not independently certified knowledge. The host supplies the session and its clock; the model does not invent a historical knowledge cutoff.

The simplified proposal changes the atom and literal-text surface, not the intended effects:

The simplified text rule consumes the remainder of quote/text lines literally. It must not turn sigils in a quotation into dependencies. The exact ? contextual-output and ~ internal-handle contracts remain separate decisions.

What stays outside the small model

jsEval and JavaScript generation are excluded. The same applies to algorithm implementations hidden in value.data or a template/procedure body. Coding agents may author reviewed programs; invoking an approved abstraction through a bounded interface is distinct from writing its implementation. The invocation grammar for expand requires explicit agreement.

Runtime bindings, retrieval/linking implementation choices, executable definition installation, and policy budgets belong to the host/system. Declarative AND/OR groups, comparisons, numeric requirements, and optimization objectives do not belong to this exclusion: they express the user's problem. Begin with simple conditions and progress to nested combinations. Assumption exercises require a distinct hypothetical-input contract; translating supplied assertions does not authorize inventing premises.
