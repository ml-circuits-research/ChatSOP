Small-model authoring profile

The small formalizer translates a user's statements and question into SOP. It must preserve who did what, negation, time, requested variables, and the scope of any write. It does not implement algorithms, choose execution privileges, or write the answer it hopes the system will return.

Profile proposal, not an approved whitelist. The eight core wire types below and the correction extension are a concrete educational boundary for review. The runtime inventory is broader. The executable atom grammar remains sop-agent-3; punctuation-free snippets illustrate the separate simplified proposal.

The table restricts fields, not just type names. A type being permitted cannot authorize arbitrary keyword combinations. For example, the runtime's solve.data and query.filter fields do not thereby belong to the first educational subset.

A contextual assertion followed by a question

Input: “Maria works at Acme. Does Maria work at Acme?” The following is executable sop-agent-3 spelling. Execution requires a host-created writable session with permission to admit the quoted assertion. No historical date is requested, so the query uses the runtime's present-time defaults.

@statement fact
  holds works_at(maria, acme)
  valid timeless
  source user
  quote "Maria works at Acme."

@store assert
  input $statement
  scope session

@question query
  where works_at(maria, acme)

@result solve
  query $question
  after $store

@answer cnl
  result $result
  language en

The user statement supplies a premise, not independently certified knowledge. The host supplies the session and its clock; the model does not invent a historical knowledge cutoff.

The simplified proposal changes the atom and literal-text surface, not the intended effects:

  holds works_at maria acme

The simplified text rule consumes the remainder of quote/text lines literally. It must not turn sigils in a quotation into dependencies. The exact ? contextual-output and ~ internal-handle contracts remain separate decisions.

What stays outside the small model

jsEval and JavaScript generation are excluded. The same applies to complex code hidden in value.data or a template/procedure body. Coding agents may author reviewed programs; the formalizer may eventually invoke an approved abstraction through a bounded interface without writing its implementation. expand is an optional extension requiring explicit agreement, not an implicit ninth core wire.

Runtime bindings, retrieval/linking implementation choices, rule/procedure installation, policy budgets, numerical expression programs, and advanced reasoning orchestration belong to the system or separate authoring tasks. Their exclusion from the first educational subset does not remove those system capabilities. Assumption exercises require a distinct hypothetical-input contract before inclusion; an instruction to translate supplied assertions does not authorize inventing premises.
