Small-model authoring profile

A small formalizer emits only premise, query and constraint. These declarative wires describe conditional context, logical questions and finite numeric problems. They do not write facts, select a backend, retrieve memory or claim an answer. The host compiles these declarations into an inspectable execution circuit with approved operations. Both layers use the same sop-agent-3 whitespace atom grammar; the difference is authoring permissions and effects, not syntax.

Model output ends with a query, constraint or premise-only input. It cannot declare clarify, fact, remember, pack, resolve, solve, cnl, value, jsEval or expand. These remain available in trusted general-runtime circuits. Host-approved metaprograms may generate resolve, packing, clarify, reasoning and checked rendering as needed, but cannot invent user intent, choose a speculative entity silently, or promote conditional premises to repository claims. Explicit fact/remember remains a separate trusted session-recording path.

Clarification is host-generated: when a required identity is unresolved/ambiguous, or a downstream required scalar is absent/nonunique, symbolic orchestration suspends dependent work and produces an inspectable clarify request for the user. Lack of evidence for an otherwise well-formed question is a reasoning result, not automatically a request for more input. Arbitrary unsupported prose is not magically recognized as a model-authored clarification.

One conditional statement and a question

User: “Suppose Maria works at Acme. Would Maria work at Acme?” The model describes a conditional premise and the question. No generated answer or session write is embedded here:

@context premise
  holds works_at maria acme

@question query
  where works_at maria acme

The host retains the user's original words and model-interpretation provenance outside the authored fields. It can resolve identity mentions against reviewed ontology and compile a solve operation with temporary assumptions. If the only support is this assumption, the result must remain conditional on it; no observed fact is recorded. solve.data is another local-premise route in trusted runtime circuits, while remember records explicit fact/event values only when independently authorized. Repository commit is distinct from either route.

Canonical literals: Atom terms are space-separated; use JSON double quotes to retain spaces, commas, parentheses and escapes in a single term. Use not for explicitly negative premises. A whole-line clarify.text can contain ordinary text; generated free text should be quoted. Keep ?variable, $reference, canonical symbols and keywords unquoted. A quoted mention remains unresolved until reviewed lookup; see quoted text.

What stays outside the small model

jsEval and JavaScript generation are excluded. The same applies to algorithm implementations hidden in value.data or a template/procedure body. Coding agents may author reviewed programs; invoking an approved abstraction through a bounded interface is distinct from writing its implementation. An approved host metaprogram may use expand to generate an inspectable circuit; that does not give the model authority to write its implementation.

Runtime bindings, retrieval/linking implementation choices, executable definition installation, and policy budgets belong to the host/system. Declarative AND/OR groups, comparisons, numeric requirements, and optimization objectives do not belong to this exclusion: they express the user's problem. Begin with simple conditions and progress to nested combinations. Assumption exercises require a distinct hypothetical-input contract; translating supplied assertions does not authorize inventing premises.
