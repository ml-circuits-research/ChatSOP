All wire types

goal

A goal states the conjunction a plan should reach in a symbolic world. It is a desired state, not evidence that the state exists. Only trusted system/tool circuits may author goals; model-authored declarative input cannot.

SOP syntax: @id type, exactly two leading spaces on each field line, $id for a computed value, ~id for a declaration handle, and ?x for a local logic variable or an output name. Atoms use [not ]predicate term1 [term2 [term3 [term4]]] with one to four whitespace-separated terms; lowercase predicate names, canonical symbols, JSON-quoted strings or safe integers. Parenthesized predicate(arg, …) and comma-separated arguments are not executable syntax.

Fields and inputs

KeywordCardinalityAccepted value, default and effect
whereRepeatable; requiredAt least one repeatable predicate atom. Every where is part of the desired conjunction; variables use ?name notation.

Use a ~goal handle or $goal value for plan goal. The goal is not a query declaration and cannot serve as abduce query. plan data may contain a goal object but does not replace its required explicit goal field.

Result and limits

The declaration yields {kind: goal, where: [...]}. Planning converts its atoms to an internal query at runtime now and returns plans if a reachable state satisfies them; no world write occurs.

The planner tests a conjunctive target against finite facts and approved rules. A variable in the goal can match a bound state object; it does not request physical execution or imply universal quantification.

Executable examples

Destination for one robot

@arrive goal
  where located_in robot7 dock

A planner can search for a symbolic state containing that exact destination atom.

Conjunctive readiness

@ready goal
  where charged robot7
  where located_in robot7 dock

Both conditions must hold in the same reached state; one condition alone is insufficient.

Invalid or unsafe use

@bad goal
  where arrived(robot7)

The parser rejects old parenthesized arrived(robot7); use arrived robot7.
