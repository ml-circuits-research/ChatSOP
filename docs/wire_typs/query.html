query

A query defines conditions and requested results, not evidence and not an answer. It is one of the five model declarations (stated, assumed, unclear, query and constraint). The context-free model writes each condition as a match block of strings; the host links it to the positional atoms documented here, which trusted circuits write directly. where describes the relation to match; select names the variables to return. solve subsequently evaluates it using explicitly supplied local data or a selected memory view.

Every accepted keyword

KeywordCardinality / defaultAccepted value and concrete effect
whereRepeatable; at least one requiredHost form: [not ]predicate term1 ... (1–4 terms), or nested all/any/end block of atom leaves. Model form: every leaf is a match … end block with relation "PHRASE", role NAME VALUE lines (closed inventory; VALUE a quoted string as written, an integer or a ?variable) and a required polarity; the host links the phrase and role set to one predicate and fills unmentioned roles with fresh variables (query_needs_match rejects model atoms). Repeated lines are conjunctions; alternatives in any are disjunctions. Variables in a query are matched, not asserted.
selectAt most once; default emptyWhitespace-separated ?name variables bound in every relevant alternative; defines selected columns, not an output wire by itself.
modeAt most once; default select when select is present, otherwise existsselect, exists, count, explain or every; any other value fails parsing (query mode must be one of). Select mode requires a selected variable (select mode needs variables). count counts distinct projections of the select variables, or distinct whole bindings when select is absent; with a selected time variable it answers "how many times" (distinct validity intervals). explain answers "why" or "how come": it evaluates the proposition like exists and the packet adds explanation with kind derivation (rules and the facts they used), recorded (a recorded fact, no further reason) or none; it selects nothing (explain_no_select). every is a universal question: where is the restriction (the domain) and scope what must hold for each member; it is refuted when a known member explicitly fails the scope (the packet lists counterexamples), supported when every known member satisfies it and the restriction has a member, otherwise unknown. With select, members are grouped by the selected variables and the answers are the groups whose members all satisfy the scope. With mode exists a select list is accepted but has no effect. Because the default depends on another field, write mode explicitly.
scopeExactly once with mode every; otherwise absentA condition in the where form (a match block, or an all/any group of them) that must hold for every binding of the restriction; the restriction's variables are shared. "Nobody at X is certified" is mode every with a negated scope; the model never rewrites "all" as "nobody … not". A scope without mode every fails with scope_needs_every, mode every without a scope with every_needs_scope. The check covers the members known to the host.
measureAt most once; only with one selected time variablestart, end or duration: the part of the selected time variable's interval that the question asks for ("since when", "until when", "how long"). The answer is an ISO start, an ISO end (open when ongoing) or a whole number of days up to the runtime clock (unbounded without a start). The selected variable must be written as role time ?t in a match block (measure_needs_time_variable).
spanHost only; at most onceA ?variable bound to the validity interval of each answer row, written by the host when a model match block uses role time ?t on a relation that declares no time role ("When did Ana work at Acme?"). Without at or during, a query with a span looks at the whole timeline. The model asks for a time with role time ?t; a model-authored span is rejected (span is host plumbing).
filterRepeatable; default noneRestricted Boolean comparison such as ?quantity > 0, or all/any/end expression block. Filters matched values; every referenced variable must be guaranteed bound by where.
atAt most once; default runtime now; exclusive with during (Use at OR during)In model output at, during and asof take a JSON-quoted temporal expression as written (at "June 2025"), which the host normalizes or asks about. Host form: ISO date/UTC instant (or beginning/open accepted by instant parser); a whole-field $value can supply an instant. Selects valid-time instant. The default is not neutral: a query with neither at nor during is evaluated at the runtime clock, so claims whose validity ended in the past do not match. Write at explicitly when the time matters.
duringAt most once; exclusive with attimeless or ISO/UTC START END interval, inclusive/exclusive; selects overlapping valid-time window, not necessarily complete-window support.
asofAt most once; default runtime nowISO/UTC knowledge cutoff or whole-field $value instant; limits repository history visible to retrieval.
limitAt most once; default 100Safe integer 1–10,000; caps returned answers. Truncation means result is incomplete.

Which books are on the north shelf?

Two local catalog claims are grouped only because solve.data takes one value. The query asks about shelf_north, so shelf_south does not match; solving evaluates this question without recording either fact in a session.

@north fact
  holds on_shelf book_a shelf_north
  valid timeless

@south fact
  holds on_shelf book_b shelf_south
  valid timeless

@catalog pack
  items $north $south

@question query
  where on_shelf ?book shelf_north
  select ?book
  mode select

@answer solve
  query $question
  data $catalog
  output ?book many

A complete answer can bind $book to ["book_a"]; many requests a collection, not independent truth certification. The following asks a different question: how many distinct shelf bindings match?

@north fact
  holds on_shelf book_a shelf_north
  valid timeless

@other fact
  holds on_shelf book_c shelf_north
  valid timeless

@books pack
  items $north $other

@count query
  where on_shelf ?book shelf_north
  mode count

@total solve
  query $count
  data $books
  output ?number count

The count port ?number names a result, not a variable from the query; with both facts admitted, the count is two.

A context-free model question

@q query
  where all
    match
      relation "works at"
      role subject ?who
      role object "Alpha Lab"
      polarity affirmed
    end
    match
      relation "member of project"
      role subject ?who
      role object "Delta Project"
      polarity affirmed
    end
  end
  select ?who
  at "1 September 2026"

"Who worked at Alpha Lab and on the Delta Project on 1 September 2026?" The date is copied as written; the model has no clock. The host links the phrases to works_at and project_member, resolves the names, normalizes the date and compiles the atom query works_at ?who lab_alpha and project_member ?who project_delta.

@q query
  where match
    relation "works at"
    role subject ?who
  end

A match block states its polarity explicitly, like every proposition.

Question forms of the model language

Each question word has one formalization (DS021); Question types maps all eighteen corpus question types to their forms with English and Romanian examples. "Does everyone on the Delta Project work at Alpha Lab?" is a universal question:

@q query
  mode every
  where match
    relation "member of project"
    role subject ?m
    role object "Delta Project"
    polarity affirmed
  end
  scope match
    relation "works at"
    role subject ?m
    role object "Alpha Lab"
    polarity affirmed
  end

"When did Maria work at Alpha Lab?" asks for the validity interval with a time variable; the host binds ?t to the interval of the matched fact:

@q query
  select ?t
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

"Since when does Maria work at Alpha Lab?" adds measure start; "until when" is measure end, "how long" measure duration:

@q query
  select ?t
  measure start
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

"How many times did Ana work at Beta Lab?" counts distinct intervals:

@q query
  mode count
  select ?t
  where match
    relation "works at"
    role subject "Ana"
    role object "Beta Lab"
    role time ?t
    polarity affirmed
  end

"Where is Alpha Lab?" asks for the location role ("how" asks for the instrument role in the same way):

@q query
  select ?place
  where match
    relation "located in"
    role subject "Alpha Lab"
    role location ?place
    polarity affirmed
  end

"Why does Maria work at Alpha Lab?" asks for the derivation:

@q query
  mode explain
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    polarity affirmed
  end

@q query

  select ?who
  where match

  end

"Why" asks about one proposition; it selects nothing.

@q query
  select ?t
  span ?t
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

The model asks for a time with role time ?t; the host writes span.

@q query
  select ?t ?u
  where all
    match
      relation "works at"
      role subject "Maria"
      role object "Alpha Lab"
      role time ?t
      polarity affirmed
    end
    match
      relation "member of project"
      role subject "Maria"
      role object "Delta Project"
      role time ?u
      polarity affirmed
    end
  end

One query asks for at most one time; two times are two queries.

Invalid: unbound output variable

@bad query
  where on_shelf ?book shelf_north
  select ?building
  mode select

This atom parses, but lowering cannot select a variable not bound by where. See Boolean conditions for supported alternatives.
