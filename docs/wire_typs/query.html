Wire index · fact · solve · all/any/end

query

A query defines conditions and requested results, not evidence and not an answer. It is one of the six model wire types (stated, assumed, unclear, query, constraint and unparsed). A query may carry clause links (a condition that applies only to it, a temporal clause that bounds its period) and may take the answers of another query as a role value ($q chaining). The context-free model writes each condition as a match block of strings; the host links it to the positional atoms documented here, which trusted circuits write directly. where describes the relation to match; select names the variables to return. solve subsequently evaluates it using explicitly supplied local data or a selected memory view.

A scope without mode every fails with scope_needs_every, mode every without a scope with every_needs_scope. The check covers the members known to the host.

compareRepeatable; default noneWords-only comparison of a value (DS021 Q-LANG-1): compare ?v COMPARATOR operand, COMPARATOR one of above, below, at_least, at_most, equal, not_equal; the operand is an integer, a JSON-quoted string or another ?variable ("over 80": compare ?age above 80; "older than Ion": two values, compare ?a above ?b). The host reads each value as a number (a string that starts with a number, such as "2380 lei", counts as that number); when an ordering comparison meets a value that is not a number the answer is not_computable. A yes/no question whose known values all fail the comparison is answered no. Alternatives are an any group: compare any, then ?bank equal "BT" and ?bank equal "UniCredit" lines, then end (also all, nested).
exceptRepeatable; default noneWords-only exclusion: except ?x "Ana" ("besides Ana"). The host resolves the quoted value like a role value and keeps only bindings where ?x is a different entity.
rankAt most once; default noneSuperlative (Q-LANG-1): rank highest ?v or rank lowest ?v ("the cheapest", "the oldest"), optionally followed by position N ("the second largest": the rows with the N-th best distinct value) or top N ("the three largest": the rows among the N best distinct values). The host keeps the rows whose numeric value is the best; ties keep every tied row. No numeric value at all is not_computable; a position beyond the number of distinct values gives no row. A ranking is valid only over a complete view of the facts: over a partial slice the answer is incomplete, never the best of the part.

The host binds each to the validity interval of its own match and compares the starts (same_time: overlapping intervals); unknown starts give unknown. The host appends leaves I J in the generated circuit.

The model decides nothing.

Which books are on the north shelf?

Two local catalog claims are grouped only because solve.data takes one value. The query asks about shelf_north, so shelf_south does not match; solving evaluates this question without recording either fact in a session.

@north fact
  holds on_shelf book_a shelf_north
  valid timeless

@south fact
  holds on_shelf book_b shelf_south
  valid timeless

@catalog pack
  items $north $south

@question query
  where on_shelf ?book shelf_north
  select ?book
  mode select

@answer solve
  query $question
  data $catalog
  output ?book many

A complete answer can bind $book to ["book_a"]; many requests a collection, not independent truth certification. The following asks a different question: how many distinct shelf bindings match?

@north fact
  holds on_shelf book_a shelf_north
  valid timeless

@other fact
  holds on_shelf book_c shelf_north
  valid timeless

@books pack
  items $north $other

@count query
  where on_shelf ?book shelf_north
  mode count

@total solve
  query $count
  data $books
  output ?number count

The count port ?number names a result, not a variable from the query; with both facts admitted, the count is two.

A context-free model question

@q query
  where all
    match
      relation "works at"
      role subject ?who
      role object "Alpha Lab"
      polarity affirmed
    end
    match
      relation "member of project"
      role subject ?who
      role object "Delta Project"
      polarity affirmed
    end
  end
  select ?who
  at "1 September 2026"

"Who worked at Alpha Lab and on the Delta Project on 1 September 2026?" The date is copied as written; the model has no clock. The host links the phrases to works_at and project_member, resolves the names, normalizes the date and compiles the atom query works_at ?who lab_alpha and project_member ?who project_delta.

@q query
  where match
    relation "works at"
    role subject ?who
  end

A match block states its polarity explicitly, like every proposition.

Question forms of the model language

Each question word has one formalization (DS021); Question types maps all eighteen corpus question types to their forms with executed English examples. "Does everyone on the Delta Project work at Alpha Lab?" is a universal question:

@q query
  mode every
  where match
    relation "member of project"
    role subject ?m
    role object "Delta Project"
    polarity affirmed
  end
  scope match
    relation "works at"
    role subject ?m
    role object "Alpha Lab"
    polarity affirmed
  end

"When did Maria work at Alpha Lab?" asks for the validity interval with a time variable; the host binds ?t to the interval of the matched fact:

@q query
  select ?t
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

"Since when does Maria work at Alpha Lab?" adds measure start; "until when" is measure end, "how long" measure duration:

@q query
  select ?t
  measure start
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

"How many times did Ana work at Beta Lab?" counts distinct intervals:

@q query
  mode count
  select ?t
  where match
    relation "works at"
    role subject "Ana"
    role object "Beta Lab"

  end

"Where is Alpha Lab?" asks for the location role ("how" asks for the instrument role in the same way):

Clause links on a question

A condition, a temporal clause or a reason attached to a question is its own stated wire, and the query names it with one keyword line (the ten link keywords). The host acts on two kinds and reports the rest (packet clause_links): if/unless scope a supposition to this query; before/after/when/while bound the query period to until/from/during the time of a dated clause; because, so, although and so_that are not_checked and the question is answered without them.

EN “If Maria works at Alpha Lab, who works at Alpha Lab?”

@s1 stated
  relation "work at"
  role subject "Maria"
  role object "Alpha Lab"
  polarity affirmed
  certainty supposed

@q query
  select ?who
  where match
    relation "work at"
    role subject ?who
    role object "Alpha Lab"
    polarity affirmed
  end
  if $s1

The supposition is used only by q: the answer maria is hypothetical and rendered with "Condition: You supposed: …"; the link is {"keyword": "if", "type": "condition", "status": "applied", "effect": "condition_scoped"}. Without the if line the supposition would apply to every query of the turn.

The clause has a readable time (valid from), so before $s1 becomes the query period until 1 March 2026 (status: "applied", effect: "until"). An undated clause, or a query that already has at/during, leaves the link not_checked (reason untimed or query_has_time).

A question on the answers of another: $q

"Who is on the Delta Project, and where do they work?" asks the second question about the answers of the first. The second query writes $q as a role value; the host inlines q's conditions with a fresh variable (a join) and answers both. The named query must select exactly one variable in mode select (reference_query_not_single).

A $s value naming a stated or assumed wire is a proposition used as an argument ("Is it fair that Maria works at Alpha Lab?"). No engine decides such a question: it is answered not_computable, and the answer shows how it was understood, with the argument written as "[work at]".

EN “Maria works at Alpha Lab. Is that fair?”

@s1 stated
  relation "work at"
  role subject "Maria"
  role object "Alpha Lab"
  polarity affirmed
  certainty asserted

@q query
  where match
    relation "be fair"
    role subject $s1
    polarity affirmed
  end

  mode every
  where match
    relation "member of project"
    role subject ?m
    role object "Delta Project"
    polarity affirmed
  end

A universal question states what must hold for each member.

@q query
  where match
    relation "member of project"
    role subject ?m
    role object "Delta Project"

  scope match
    relation "works at"
    role subject ?m

  end

A scope belongs to mode every.

@q query
  measure start
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

A measure applies to exactly one selected time variable.

@q query
  mode explain
  select ?who
  where match
    relation "works at"
    role subject ?who

  end

"Why" asks about one proposition; it selects nothing.

@q query
  select ?t
  span ?t
  where match
    relation "works at"
    role subject "Maria"
    role object "Alpha Lab"
    role time ?t
    polarity affirmed
  end

The model asks for a time with role time ?t; the host writes span.

@q query
  select ?t ?u
  where all
    match
      relation "works at"
      role subject "Maria"
      role object "Alpha Lab"
      role time ?t
      polarity affirmed
    end

      relation "member of project"
      role subject "Maria"
      role object "Delta Project"

      polarity affirmed
    end
  end

One query asks for at most one time; two times are two queries, unless order ?t before ?u compares them.

Invalid: unbound output variable

@bad query
  where on_shelf ?book shelf_north
  select ?building

This atom parses, but lowering cannot select a variable not bound by where. See Boolean conditions for supported alternatives.

Knowledge language: query

What it is for

Pick the mode from the question: "who works at Alpha?" is select; "is Lyon in France?" is exists; "how many?" is count (a lower bound over an open relation); "is everyone certified?" is every with a scope; "why?" is explain; "how do I...?" is plan. What-if needs no mode: the user's "if ..." is a fact or stated with status supposed linked by if $id, and the answer is conditional on it. The five reasoning modes why_not, plan, abduce, conform and procedure are described on Query modes.

Examples

@located_in predicate
  args subject:entity location:entity
@f1 fact
  holds located_in paris france
@f2 fact
  holds located_in lyon france
@f3 fact
  holds located_in rome italy
@q query
  where located_in ?city france
  select ?city
@q query
  mode count
  where located_in ?city france
  select ?city

The count is a lower bound (located_in is not declared closed).

@q query
  mode exists
  where located_in lyon france

Time: throughout

@works_at predicate
  args subject:entity object:entity

@f1 fact
  holds works_at ann alpha
  valid 2020-01-01 2023-01-01
@f2 fact
  holds works_at ann beta
  valid 2023-01-01 open
@q query
  where works_at ann ?c
  select ?c
  during 2021-06-01 2023-01-01

during returns only alpha, because Ann worked at Beta only from 2023; overlaps 2021-06-01 2024-01-01 would return both.

Invalid: every without a scope

@q query

  where member ?m delta

Common mistakes

  1. every without scope, or scope on another mode.
  2. Selecting a variable that where does not mention (select_unbound).
  3. More than one of at, during, overlaps; and reading during as "at some instant": it means throughout.
  4. via or trace outside the modes that take them; the model never writes them.
  5. Expecting a count over an open relation to be exact: it is a lower bound (bound at_least).
