ChatSOP Documentation

ChatSOP has one goal: to beat small LLMs at reasoning through symbolic processing, and to help small LLMs reason symbolically. A user submits a checked SOP circuit, or asks in plain language and lets a coding agent (omp) write the circuit. The validator checks it, the KnowledgeLinker links its names to authorized, time-aware knowledge, the StrategyRouter sends the problem to the right reasoning strategy, and the result comes back with evidence and a deterministic English rendering.

The circuit in one example

The coding agent sees the user's message and the memory vocabulary and writes only circuits. "Where does Maria work?" becomes a query whose names are strings; the KnowledgeLinker links "Maria" to an entity, the router chooses a strategy, and the answer is rendered from the result packet.

@q query
  where match
    relation "works at"
    role subject "Maria"
    role object ?org
    polarity affirmed
  end
  select ?org

What the user stated stays turn-local evidence; anything the agent adds is marked assumed; an unintelligible, empty or undecidably ambiguous message is unclear. The agent never answers and never states a fact; a question the system cannot compute is answered "I understood the question as ...; I cannot compute this kind of answer yet".

The knowledge language

What the system knows is written separately from the chat, from sources, as knowledge wires (predicate, fact, rule, default, integrity, aggregate, action, method, norm, procedure) by a coding agent or the owner, and validated by sop/knowledge/. Several reasoning strategies answer questions over the same wires and are compared on one smoke suite. The user manual is the section "Knowledge wires" of DS004, with one help page per wire; the task procedure for compiling a long text into wires is skills/sop-wire-authoring/SKILL.md.
