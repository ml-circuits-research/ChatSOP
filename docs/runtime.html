Overview / Runtime

ChatSOP Documentation

Local users run typed SOP circuits against reviewed knowledge and receive checked results. The host, not a source document or a language model, chooses the active user, permissions, profile, and approved definitions.

Local CLI

From the repository root, use node server/cli.mjs help for the supported local commands. node server/cli.mjs init publishes a small reviewed fictional fixture; node server/cli.mjs run --file examples/query.sop executes a circuit. validate --file <path> checks and canonically prints a program; compile-smt and compile-prolog export the supported typed subsets. The CLI also provides chat, fork, commit, discard, stats, maintain, and gc. For gc, no --apply means a dry run. A chosen config profile belongs under config/; model-backed chat requires a separately configured model endpoint.

Execution and publication

The parser checks each typed declaration. SOP relations use whitespace-separated atoms such as works_at maria acme, with no parenthesized arguments or comma separators; arithmetic and solver-internal languages retain their own syntax. The model-origin surface admits only premise, query, and constraint. A premise is conditional interpreted context with holds and optional valid (default timeless), not a sourced fact or a write; the host keeps the original input text and model-interpretation origin distinct. Approved host code compiles an inspectable full circuit for identity lookup, conditional assumptions, reasoning and rendering, and generates a specific clarify wire if identity is unresolved/ambiguous or a required scalar is missing/nonunique. Lack of evidence alone is not a clarification request. A linker selects approved definitions and retrieves appropriate premises from a memory engine; the selected reasoning strategy computes a result, binding, evidence, and completeness information. CNL renders the resulting state without changing it. A scalar output is not fabricated when retrieval or inference cannot justify a unique value. In a trusted full circuit fact constructs a sourced value, solve.data uses supplied premises temporarily without recording them, and explicit remember records authorized facts/events in the selected session while rejecting premise inputs. Recording is not proof of truth or global publication; committing the session is a separate host action. Ingestion records source and time and passes privileged publication through host review; a document or model can propose, not directly certify or install a rule.

The repository separates users, sessions and forks. A claim's valid interval is distinct from when the claim became known; correction and retraction cannot be erased by choosing another memory engine. Referenced snapshots remain reachable GC roots. A missed retrieved premise is not a proof that it is false.

Worked example: declarative question to checked answer

The author writes only declarative SOP; the host builds the circuit, and every reported value below comes from an actual runtime result over the reviewed fictional fixture.

Answer supported by reviewed knowledge

@question query
  select ?org
  where works_at maria ?org

Host-generated circuit:

@question query
  select ?org
  where works_at maria ?org

@host0 solve
  query $question

@host1 cnl
  result $host0
  language en

Observed result: status: supported, ?org = "lab_alpha", evidence works_at maria lab_alpha with SOURCE demo; no model authored the solve or cnl steps.

Conditional interpretation stays hypothetical

@context premise
  holds parent carina ana

@question query
  select ?who
  where parent carina ?who

The generated circuit adds assume $context to its solve. Observed result: status: supported with hypothetical: true, ?who = "ana", evidence SOURCE model-interpretation, and the session still holds zero repository claims after the turn — the premise is conditional conversation context, not a recorded fact.

Both outputs were produced on 2026-09-27 by executing these programs with the runtime against tests/fixtures/bootstrap.sop at a fixed evaluation time.

Alternative routes and limits

Profiles may independently select memory.engine among Weaver, Holo, SQLite, scan and hybrid implementations and policy.reasoningStrategy as reference JavaScript or advanced optional SWI-Prolog/Z3 routing. The result records the actual route and fallback; advanced with a JavaScript fallback is not a Prolog or Z3 measurement. Associative recall produces candidates subject to verification, and retaining exact SQL premises changes the completeness contract. This local CLI and its limited local model inference adapter do not constitute a complete OpenAI-compatible ChatSOP HTTP service.
