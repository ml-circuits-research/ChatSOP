## Introduction

A [formalizer](wiki.html#definition-formalizer) is trained to map the user's message alone (no shortlist, identifiers, knowledge or clock) into declarative SOP — `stated`, `assumed`, `unclear`, `query`, or `constraint`, written as strings ([DS021](specsLoader.html?spec=DS021-model-surface.md)) — not execution-session plumbing, sourced facts, or clarification text; an optional [verbalizer](wiki.html#definition-verbalizer) rewrites an already determined CNL result without changing its meaning. Training is distinct from operating the local symbolic CLI, publishing reviewed facts, and proving semantic accuracy.

## Core Content

### Roles and input contracts

The model target is declarative `.sop`, not an executable host circuit, a JSON fact database, or free-form Prolog/SMT-LIB. A model `stated` or `assumed` proposition carries a quoted relation phrase, closed-inventory roles with values as written in the message, polarity and optional quoted time, without `source`, `quote`, or permission to store it. The host keeps original text apart from admitted facts; separate approved operations link the strings to the lexicon and assemble an inspectable circuit with identity lookup, evidence or assumptions, solving, CNL and, when a relation, identity, date or required scalar is unknown or ambiguous, generated `clarify`. Missing evidence alone does not require clarification. `fact`, `remember`, `pack`, `resolve`, `solve`, `cnl`, `clarify`, `value`, `jsEval`, and `expand` are not small-model target wire types. The formalizer receives no symbols or definitions at all, and no authority to install them; no metaprogram may guess an ambiguous identity or turn a statement or assumption into a stored fact. The instruction-free training prompt is exactly the message. The verbalizer must preserve truth status, explicit negation, hypotheses, time, quantities, evidence and incompleteness. Deterministic CNL is the baseline for evaluating the formalizer; fluent rewriting does not fix invalid declarations or mistaken knowledge. A model artifact is not established by a training script or config alone.

**Multilingual formalizer, English knowledge.** Fine-tuning teaches one skill: turning a message in any supported input language into SOP whose content words are normalized in the message's language (DS021 "Input languages and content words", owner decision D1 of 2026-09-29); the host dictionary translates them before linking. Romanian is the first non-English input language because the owner can review it directly; further languages follow the same recipe: generator constructions and noise models for the new language (DS022), dictionary entries for it, the same target convention, and per-language evaluation slices (DS016). Proper names are never translated. No language-specific knowledge or reasoner is ever introduced.

### Runtime and artifact boundary

Node `.mjs` owns orchestration and portable checks; Python under `training/python/` is retained for indispensable ML libraries such as model loading, tokenization, optimization, adapter serving, and export that cannot be replaced responsibly by built-ins. The training controller lists its commands via `node training/cli.mjs --help`. Pinned base caches belong at `models/<model>/bases/<40-character-revision>/`; run-owned `identity.json` and `latest`/`best` checkpoint records belong at `models/<model>/<run>/<role>/`, preserving dataset and recipe identity. Source model identifiers and exact revisions must accompany actual artifacts. `server/` consumes an explicitly configured local model inference endpoint and may use CNL without a verbalizer. A locally running inference adapter is not the ChatSOP client-facing OpenAI service and does not establish `/v1/models` or `/v1/chat/completions` support.

### Startup and experimental constraints

Before any GPU-intensive launch, check exclusive ownership/lock, disk, host and device memory, Python and ML package compatibility, model revision, immutable dataset, resumable checkpoint, and writable run directory. A missing prerequisite must fail before substantive GPU or artifact work; the explicit `download` command must not be confused with implicit startup installation. `node training/cli.mjs` is the sole trainer/controller in both reviewed native Python and rootless Podman modes, and only one GPU-intensive worker may run per machine across those modes; concurrent GPU jobs, unrelated process kills, and cleaning unknown checkpoints are outside this contract. The retired orchestration shell scripts are not an alternative execution path. A successful Python import or dry-run does not establish hardware readiness or an accurate model. For the formalizer, `best` is selected using generated full-development-set predictions evaluated by `eval/run.mjs`, with execution-equivalence numerator primary and syntax numerator breaking ties; invalid reference or denominator mismatch must fail closed. Verbalizer and shared dev-…loss selection is only diagnostic, not a faithfulness criterion. Recovered checkpoints and claims must belong to the recorded run; holdout and independent human review remain necessary for model comparison and promotion under [DS008](specsLoader.html?spec=DS008-data-evaluation.md). External weight and corpus redistribution permissions remain independently reviewable.

### Encoder-decoder (seq2seq) formalizer

A recipe with `"architecture": "seq2seq"` (first used by experiment `formalizer-mt-v1`, `config/train-opus-mt.json`) fine-tunes an encoder-decoder translation model instead of a decoder-only chat model. The encoder input is the user's message and nothing else (no chat template, instruction or context); the decoder label is the SOP target. Because translation tokenizers normalize newlines and runs of spaces away, both sides pass through the reversible line encoding of `training/python/seq2seq_text.py`: a target line break followed by 2*K spaces of indentation is the added token `<nK>`, and a message line break is `<n0>`. `common.encode_seq2seq_row` refuses any row whose target does not decode back exactly, and any source or target longer than the recipe's `max_source_length`/`max_target_length` (no truncation). For Marian, the static sinusoidal position table is extended to `max_position_embeddings` at load (its first rows are checked equal to the base's) and kept frozen. The same selection policy applies (`select_final_only`, capped greedy decoding of the full development split). `node training/cli.mjs predict` (also allowed inside the training container) writes `{id, sop}` predictions from a seq2seq checkpoint with `training/python/predict_seq2seq.py`, reading only each suite row's `id` and `question`.

Recipes may declare interim checks (`interim_check_rows`, `interim_checks_first_epoch`): after each fraction of the first epoch and at every epoch end the trainer records the development loss and a greedy decode of a fixed stratified development sample scored for parse validity and tolerant execution equivalence (`interim-checks.jsonl`), and stops early when the run is failing (from the end of epoch 1: parse validity below 50%, or more than half the sample empty or capped) or has plateaued (a check improves neither the tolerant count nor the development loss over the previous one; the current model is then selected). This implements the owner's early-stop rule of 2026-09-29.

### Dataset qualification and model references

Qualification is allowed pre-training work. Audit prompt and target lengths with the real tokenizer of the candidate model and refuse silent truncation. Archive the model identity, ontology, generator, seed, accepted-row hashes and prompt with any model trained on them, and regenerate and re-evaluate the data whenever a predicate or wire meaning changes. Candidate base models are described by their publishers' model cards, for example SmolLM2 135M/360M Instruct (<https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct>), Gemma 3 270M IT (<https://huggingface.co/google/gemma-3-270m-it>) and Qwen3 0.6B (<https://huggingface.co/Qwen/Qwen3-0.6B>); a recipe may replace a shipped chat template (`chat_template`) when it would add text to the model input, as SmolLM2's injected persona system prompt does; adapters use Hugging Face PEFT LoRA (<https://huggingface.co/docs/peft/en/developer_guides/lora>) and export or serving uses llama.cpp (<https://github.com/ggml-org/llama.cpp>), archived with its exact commit. A model card is not evidence of Romanian or SOP performance.

### Rootless Podman boundary

The optional ARM64 training image is built explicitly from the reviewed `training/container/` definition with pinned source and package versions. Runtime uses an already present local image (`--pull=never`), NVIDIA CDI `nvidia.com/gpu=all`, a repository code/dataset mount and narrowly writable models/reports/cache mounts; it invokes the same Node controller rather than an independent trainer. No privileged container, host-wide home mount, implicit package/model download, driver mutation or cross-project cache sharing is part of this contract. Verify rootless cgroup v2 CPU, memory and PID limits on the actual host, not from configuration alone; preserve inspection artifacts for any cgroup OOM or termination. On GB10 unified memory the host and CUDA budgets overlap, and cgroup memory limits may not bound all driver/device allocations. Check both available host RAM and reported device free memory before/after GPU work. Never force page-cache reclamation with memory allocation or `drop_caches`, restart the driver, kill workers by generic process name or automatically restart without a finite operator-approved budget. Stop only the owned container/launcher; validate checkpoint digests, optimizer and RNG state before resuming, and retain the semantic best and run reports. The concrete documented commands and host-specific observations are in `skills/spark-training/SKILL.md`. The 2026-09-27 local image build and `spark-preflight-1` CDI probe passed: the latter recorded effective six-CPU/32-GiB/zero-swap/256-PID/1-GiB-shm limits and a small BF16 forward/backward on NVIDIA GB10, exit 0 with no reported OOM kill. Provenance and raw evidence live under `models/.container-runs/`. This is infrastructure qualification only, not training, a controlled stop, a GPU allocation bound, a cache-pressure test or model-quality evidence; explicit user approval remains required.
