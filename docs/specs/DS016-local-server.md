# DS016 — Local OpenAI-compatible server

## Scope and authority

`server/http.mjs` provides a localhost HTTP façade. The only conversational execution path is `Agent.turn` → model inference client (`server/llm.mjs`) → validated declarative SOP → host-generated `Runtime` circuit. The model may author only `premise`, `query`, or `constraint`; it cannot choose `remember`, claim documentary provenance, invoke tools, or publish knowledge. A separately authenticated, explicitly supplied `chatSop.trustedSop` circuit may contain `fact`, `event`, and `remember` wires only; it runs as a trusted user action in that user's session before the question. The receipt of a stored claim is returned as `chatSop.system_receipt` and can identify the target of a later correction. This is not model output or automatic ingestion. Trusted writes persist in the repository's private session; they are not committed to another user's state or published as base knowledge.

## Serving profile and backend qualification

Select `promptProfile` explicitly: `formal` sends `formalPrompt` (system instructions followed by CONTEXT + MESSAGE) to a base model; `bare` sends exactly `barePrompt` (CONTEXT + MESSAGE) to a qualified fine-tuned model. An explicit `CHATSOP_PROMPT_PROFILE` may supply the profile when the runtime configuration omits it; a mismatching environment/configuration pair is rejected at startup. Mixing the two prompt profiles invalidates model evaluation. Neither runtime.json nor this source tree ships a trained ChatSOP checkpoint. The configured `formalizer.url` must point to an independently started inference endpoint; no weights are loaded by this server. A `bare` backend additionally requires configured `backendIdentity` and a matching `chatSopIdentity` in the formalizer's GET `/v1/models` entry. Both identities must match on `model_id`, `revision`, `tokenizer_sha256`, `dataset_version_sha256`, and `prompt_profile: bare`; the backend operator must verify these values against the checkpoint and tokenizer artifacts before serving. These declarations are an interoperability guard, **not cryptographic attestation or evidence that a checkpoint exists**. Adapter/base compatibility and actual training qualification remain operator prerequisites. A mismatched or missing identity refuses readiness. `formal` mode requires the configured formalizer model in its reachable model listing; GET `/readyz` returns 503 with `{ready:false,model_available:false}` if absent or unreachable, never a pretend success.

## HTTP contract

`GET /healthz` reports only process liveness (no authentication; no model readiness). All `/v1/*` paths and `/readyz` require a bearer token. `GET /v1/models` lists the façade model only when ready. `POST /v1/chat/completions` accepts one **new** `{role:'user',content:'...'}` message, the configured façade `model`, optional `conversation_id` (default `default`), optional `stream`, and optional `chatSop.trustedSop`. The server, not the client-supplied message list, owns conversation history; arbitrary prior roles, tools/function calling and unsupported generation parameters are refused. Supplying `user` is optional but must equal the authenticated principal. The default `CHATSOP_API_KEY` authenticates principal `local`; embedded integrations can pass separate named bearer credentials via `createServer({authTokens:{alice:'...',bob:'...'}})`. A shared token is a shared identity and cannot provide multi-user isolation.

The normal completion is an OpenAI chat-completion envelope with `choices[0].message.content` (host CNL, not an uncertified rewrite) and `chatSop` containing `model_sop`, generated `circuit`, proof `provenance`, reasoner `backend`, reported `fallback`, `completeness`, authoritative `cnl`, `status`, clarification `pendingSop` and `required` when applicable, active `prompt_profile`, formalizer model, and optional trusted circuit/receipt. Provenance is observed or conditional as recorded by the runtime; no fabricated confidence is implied. `stream:true` emits the **already validated complete result** in SSE chat-completion chunks and terminates with `data: [DONE]`; it does not stream unverified model tokens. If the client disconnects, no additional HTTP chunks are sent; an already started inference or write is not rolled back. Explicit `/v1/responses`, `/v1/embeddings`, `/v1/tools` and chat tools receive errors rather than mock behavior.

## Locality, limits, persistence and errors

The default listener is `127.0.0.1:3000` (`CHATSOP_HOST`, `CHATSOP_PORT`), and remote binding requires explicit `CHATSOP_ALLOW_REMOTE=1` plus external transport security and access controls. At least one bearer credential is mandatory; tokens must be unique per principal and at least 16 bytes. `limits.maxRequestBytes` (default 65536), `maxContextBytes` (4800), `maxConcurrent` (4) and `timeoutMs` (30000) can be supplied through `config.server.limits` or `createServer({limits})`. Request byte and message-context oversize return 413; overload returns 429; same-session concurrent calls return 409. Formalizer fetch uses the smaller of backend and request timeout; on timeout the façade returns 504 while the in-flight operation retains its concurrency slot until settled. Do not retry a timed-out trusted write without checking the session receipt/state. Errors have generic messages and must not echo request content, private claim details, model endpoint bodies or bearer keys.

Repository sessions are keyed by base, authenticated principal and `conversation_id`. Agent conversational context is stored alongside the repository in a private per-conversation state file; context is reloaded after restart, while repository writes survive independently. Keep the repository and conversation directory inaccessible to other local accounts, and do not expose this API publicly without an independent security review. A real model-backed smoke, calibrated model quality, tokenizer equivalence and checkpoint provenance **remain unverified** in this repository; the HTTP tests use an actual deterministic mock HTTP endpoint to prove wire behavior without neural inference.
