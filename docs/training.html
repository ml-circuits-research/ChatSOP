Overview / Training

ChatSOP Documentation

Model training has two separate tasks: a formalizer proposes declarative SOP from a question and supplied context; an optional verbalizer rewrites an established CNL answer. Model targets permit only premise, query, and constraint, using whitespace-separated atoms such as where works_at maria ?company, not parenthesized/comma-delimited atoms. A model premise has holds and optional valid (default timeless) and remains conditional: it is not a sourced fact, proof, or repository write. Host-approved code expands the problem into an inspectable execution circuit; fact, remember, pack, resolve, solve, cnl, and clarify are trusted operation types, not small-model lessons. The host generates clarify for a real missing/ambiguous identity or missing/nonunique required scalar; unknown evidence alone is not a clarification request. The model neither approves new knowledge nor makes a conclusion proven by choosing fluent wording.

Cases and source rights

Each semantic case links the intended meaning, validated SOP target, linguistic variants and provenance. All paraphrases and language variants of the same meaning share a split; related contrasts and semantic duplicates are grouped so a test question does not leak into training through another phrasing. Seed data in datasets/seed/ is an executable fixture, not independent gold or human semantic certification. Raw material, transformation, generator, review, and rights must be recorded for any new corpus; software licensing does not cover imported model weights or third-party datasets.

Model boundaries

Node .mjs handles orchestration and validation; indispensable ML operations stay under training/python/ and require compatible Python, model libraries, device prerequisites, and an explicit run directory at models/<model>/<run>/. The host checks ownership/lock, disk, memory, revision, immutable data, and checkpoint before GPU-intensive work. Configuration and adapter code do not establish the existence or accuracy of a trained checkpoint. Deterministic CNL lets the operator evaluate a formalizer without conflating a verbalizer's fluency with a correct answer.

Qualified GPU environment and recovery

The recommended optional GPU path is an explicitly built rootless Podman image using NVIDIA CDI, the existing Node training controller and a pinned ARM64 CUDA/Python environment; instructions and stop/recovery commands live in the Spark training skill. A reviewed native Python environment is also possible: run TRAIN_PYTHON=<venv>/bin/python node training/cli.mjs preflight, qualify BF16 forward/backward, and only after new user approval use node training/cli.mjs train --model qwen --run <new-run> --role formalizer --data <reviewed-dataset> --qualification <qualification.json> --authorization <new-user-approval.json> with the same interpreter. Only one GPU-intensive worker may run across native and container modes. The controller's lock and digest-marked checkpoint identity guard resume; inspect models/.training.lock/owner.json and models/<model>/<run>/<role>/, never kill a process by a generic name. On GB10 unified memory device and host free-memory readings overlap, and a container memory limit does not by itself guarantee a GPU/device allocation limit. Check effective cgroup limits and OOM counters, stop only the owned launcher/container, keep the best and reports, and resume only a complete matching checkpoint. Do not squeeze caches, restart drivers or repeatedly auto-restart failed training. An image build, import, dry-run or generated fixture is not proof of model quality or training-pressure safety.

Current training authorization

The operator has explicitly deferred all model training until a new explicit approval. Image build and dependency setup, CUDA infrastructure preflight, safe container stop, dataset qualification, and evaluation of existing artifacts may proceed; do not invoke train, --resume, fine-tuning, optimizer steps or a training smoke run. Completing preflight or preparing a corpus does not grant permission to train. Training commands in this chapter describe the future procedure only.

Deterministic corpus pilot

node tools/datasets/build-pilot.mjs --out <new-train-dir> --eval-out <separate-new-eval-dir> --worlds 100 --seed 731 creates distinct train/dev and sealed test directories from synthetic family templates; choose new output directories because the generator writes named files. node tools/datasets/validate.mjs --manifest <new-train-dir>/manifest.json --execute checks the manifest, split grouping and fixture outcomes against a separate graph oracle in isolated runtime sessions. Dataset-conversion code lives under tools/datasets/; datasets/ holds only data artifacts. These generated cases have not acquired third-party corpus rights or human source review; a fixture-specific validation result does not measure a trained model.

Bounded evaluation paths

node eval/suites/core.mjs --out <new-suite.jsonl> exports twelve EN/RO rows in six separate case families, authored independently of pilot templates; the suite is neither human-validated nor a statistically sufficient sample. node eval/run.mjs --file <suite.jsonl> --predictions <predictions.jsonl> --out <report.json> requires one explicit {id,sop} prediction per row; --config <runtime.json> selects a configured endpoint instead. It reports parsing, execution, canonical match, UNKNOWN, paraphrase and hard-negative slices with stage timings. These finite-world comparisons neither establish a model's identity nor prove universal equivalence. eval/verbalizer.mjs separately checks a limited verbalizer numeric guard without certifying paraphrase fidelity.

Evaluation and reporting

With a fixed corpus and approved knowledge, evaluate predicted declarative SOP separately from the compiled gold execution circuit: parsing and runtime validity, semantic answer and proof, temporal and negative cases, ambiguity/UNKNOWN, abstentions, forbidden model operations, unauthorized persistence, model-stage latency, and per-language and per-family errors. A reasoner comparison holds the problem and premises fixed; a memory comparison holds the problem and reasoner fixed. Actual observed backend and fallback matter more than a requested label. Preserve past reports in eval/reports/history/ and attach fresh results to the run in eval/reports/current/. The reproducibility and evidence rules are in DS007 and DS008.

Report small-model NL-to-declarative-SOP fidelity (atom syntax, variables, conditional premises and problem structure) separately from host-generated execution, clarification, memory, reasoning, procedures, backend, time and provenance. Earlier mixed suites/results are not already model-track measurements; gold-program execution is not model evaluation. Define track-specific cases and denominators against the current SOP atom contract; see evaluation guidance.
