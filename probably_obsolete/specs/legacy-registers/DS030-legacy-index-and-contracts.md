# DS030 — Legacy index and contract audit

## Scope and precedence

This is a navigation and change register, **not** a second SOP contract. The source snapshot was read at `probably_obsolete/legacy/requirements/README.md`, `probably_obsolete/legacy/EXAMPLES.md`, `probably_obsolete/legacy/SOURCES.md`, and `probably_obsolete/legacy/contracts/{wire-fields.md,wires.json}`; the archived counterparts are under `probably_obsolete/legacy/`. Paths and line numbers below identify those corresponding archived files (the parent migration preserves the content and verifies these references). The old index called code and examples part of the contract and listed earlier training plans; those assertions are historical, not current authorization (`probably_obsolete/legacy/requirements/README.md:1-5,16-24`). This session's decisions supersede conflicting archived prose: the small model writes **only** `premise`, `query`, `constraint`, while an approved host compiles `resolve`, `pack`, `solve`, `cnl`, `remember`, and necessary `clarify`; atoms have whitespace-separated terms, not parentheses (`docs/specs/DS004-sop.md:14-26,35-47`). The sole current generated wire inventory lives in `sop/contracts/` (`docs/specs/DS004-sop.md:81-84`).

## Contract-file comparison

Compare *archived* `probably_obsolete/legacy/contracts/wire-fields.md` / `wires.json` against *current generated* `sop/contracts/wire-fields.md` / `wires.json`. The authoritative generation command is **`node tools/capabilities.mjs --write`**; the archived Markdown mentions retired `node tools/capabilities.js --write` (`probably_obsolete/legacy/contracts/wire-fields.md:3-5`; `sop/contracts/wire-fields.md:1-3`; `tools/capabilities.mjs:6-7`). Neither generated output was edited for this audit. Both JSON files retain `profile: sop-agent-3`, five `memoryEngines`, and the same `reasoning` tables (`probably_obsolete/legacy/contracts/wires.json:1-31`; `sop/contracts/wires.json:1-31`).

**Counting rule:** compare JSON object property paths recursively; an array is one property row (a changed array counts once, not once per element); a whole wire-type object counts once, not again for its child properties. On that basis **6 added, 4 removed, 29 changed JSON rows**; 34 legacy wire types versus 36 current. Independently, the generated Markdown has **3 added type sections, 1 removed type section, and 25 retained sections with a changed field or model-authoring permission** (24 authoring flips plus one changed field list). Translation/header wording and changed explanations are not counted as field rows. JSON adds 3 complete type rows (`resolve`, `premise`, `remember`) plus 3 notes (`pack`, `reason`, `clarify`); removes `assert` plus 3 old notes (`binding`, `trace`, `theory`); changes 24 `authoredByModel` values, 4 roles, and 1 field array. The `one`/`many`/`required`, `role`, `declaration`, `authoredByModel`, `effects`, and `note` categories below exhaust the machine-readable differences; all other shared field arrays/metadata, and top-level keys, are unchanged.
